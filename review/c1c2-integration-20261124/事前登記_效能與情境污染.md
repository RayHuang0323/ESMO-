## P1　Node：舊版路徑每 tick 耗時（TD-TAC-66）

- 規則集：
  - **P1a** `balanceTool.v24`，原生路徑，也就是 Owner 指定的「舊版 v24 路徑」。
  - **P1b** `balanceTool.v20`：旗標全關時，正式站解析出 `career.v20`，這是它的工具版。
- 對局：C2 計畫的 Z001～Z020，種子 261001～261020，模板依 C1 規則，config standard，鏡像陣容，parity 工具環境。這些是用過的種子，這裡只量耗時，不據此做任何勝負或平衡結論。
- 每場最多跑到遊戲時間 3000 秒，每次 tick 0.5，只計 tick 迴圈的耗時，不含組裝。
- 每個 tree 在自己的子行程裡跑（只載入自己的 src），執行順序是 A B B A 重複 3 輪，每個 tree 6 次。A 是 BASE，B 是 CAND。
- 指標：每次執行的「總毫秒 ÷ 總 tick」；額外成本 ＝ CAND 中位數 ÷ BASE 中位數 − 1。
- 正確性前提：兩個 tree 的每場終局狀態摘要（C1StateDigest.v1）必須完全相同，tick 數也要相同，否則直接 FAIL。理由是 v20～v24 逐 tick 不變。
- 判讀：
  - P1a、P1b 各自判讀。額外成本 ≤ 10% 為 PASS，> 10% 為 FAIL。FAIL 就停下來回報 Owner，不發布。
  - 若 BASE 自己 6 次的最大值 ÷ 最小值 − 1 > 8%，該項判為 INCONCLUSIVE，用完全相同的設計重跑一次，第二次就是最終結果。

## P2　瀏覽器：觀看、快速完成、Replay 的效能與記憶體

- 建置：BASE 與 CAND 各做一份正式預設的 production build（不開任何旗標），分別用獨立的 vite preview 提供：CAND 在 5649，BASE 在 5651。不動 5646／5647／5648。
- 瀏覽器：Chrome 157，headed（開 GPU），視窗 1280×900。每次執行都用全新的測試 Profile。
- 存檔：同一份既有存檔 `C:/Users/ifikn/esmo-measure/cs-competitive-quality-20261116/final-season/natural-season-complete.save.json`。
- 流程：走正常 MOBA 路徑，跟上一輪整合的 moba-ui-r3 相同：首頁 → MOBA → 配對 → Ban/Pick → 載入 → 戰鬥。
  - 依序 1×、2×、4× 各觀看 20 秒。
  - 再按快速完成，進結算。
  - 開 Replay 播放 20 秒，然後關閉。
- 執行順序：BASE、CAND、CAND、BASE、BASE、CAND，每個 build 3 次。
- 指標：
  - 每個速度段：requestAnimationFrame 間隔的 p50／p95、long task 總毫秒、段末的 JS heap（CDP `Performance.getMetrics` JSHeapUsedSize）。
  - 快速完成：從點擊到結算畫面出現的毫秒數，同時記錄該場的 sessionId 與比賽時長。
  - Replay：播放 20 秒期間的幀間隔 p95、播放結束時的 heap；關閉並強制 GC 之後的 heap。
  - 全程：最高 heap、console error 與 page error 的數量。
- 判讀（以 3 次的中位數比較）：
  - 快速完成耗時：CAND ≤ BASE × 1.10。若兩邊同一次的比賽時長不同，改用「毫秒 ÷ 比賽秒數」比較。
  - 各速度段與 Replay 的幀間隔 p95：CAND ≤ BASE × 1.10 ＋ 1 ms。
  - 最高 heap 與 Replay heap：CAND ≤ BASE × 1.10 ＋ 16 MB。
  - 任何一次出現產品錯誤（console error、page error）或流程失敗，直接 FAIL。
  - 任何一項超過門檻就是 FAIL，停下來回報 Owner。
- **P2b（旁證，不判 PASS／FAIL）**：用 CDP `Emulation.setCPUThrottlingRate` 4×，BASE 與 CAND 各跑一次相同流程，只記錄數字。這是桌機模擬，不代表任何真實低階裝置。

## P3　數學核心情境不互相污染

- 單一 Node 行程（CAND tree），規則集 `balanceTool.v20`～`balanceTool.v26` 共 7 個，每個 2 場。種子 262001～262014，模板依 C1 規則，parity 環境。
- 隔離基準：每一場先單獨從頭跑到結束，每個 tick 記錄 C1StateDigest.v1。
- 交錯：14 場用「v26、v20、v25、v21、v24、v22、v23……」這種交錯順序全部組裝完，再逐 tick 輪流推進，每個引擎每輪推一個 tick，直到全部結束。每一步之後記錄摘要，並檢查全域核心已回到原生（`currentSimKernel().id === "native"`）。
- 判讀：14 場在每一個 tick 都和隔離基準完全相同，而且每一步之後全域核心都是原生，才算 PASS。任何一處不同就是 FAIL，停下來回報 Owner。
