# ESMO MOBA 地圖視覺原型 v1（Milestone F）

日期：2026-07-22　　狀態：**未 commit，等待人工目視**
預覽：`?debug=moba-map-blockout`（正式遊戲流程完全不受影響）

---

## 1. 本次目標

把地圖從「看得出有東西的 debug blockout」推到「**第一眼像一張 2.5D MOBA 戰場草稿**」。

判準只有一個，而且刻意設成不靠文字：
**把所有標籤關掉之後，還能不能看出三路、河道、Dragon / Baron、四個野區、基地、塔點、主要通道。**

這不是要做 3A 成品，也沒有抄任何一款既有 MOBA 的地圖形狀。ESMO 自己的構圖規則寫在
`src/battle/moba/map/mapTerrainShapes.js` 的檔頭。

---

## 2. 與 Milestone D / E 的差異

| | D / E（之前） | F（本次） |
|---|---|---|
| 形狀來源 | 直接在 renderer 裡臨時算，畫面與驗證各算各的 | 抽出成一份 **`mapTerrainShapes.js`（純資料）**，畫面、驗證、俯視圖三方吃同一份 |
| 地圖輪廓 | 一整塊矩形草皮 | 切掉左上／右下兩個「沒有任何路經過」的死角並填成崖體，可行走區變成沿藍→紅拉長的六邊形 |
| 牆體 | 稀疏折線 → 相鄰兩點連一塊長方體（20~25 單位長的積木） | 曲線細分 + 側向擾動 + 逐段高低厚薄起伏，**平均段長 2.3 單位**的連續弧形岩壁 |
| 河道 | 一條被路面截斷成兩截的藍帶 | 四層帶（岸→床→水→淺灘），**圖層順序刻意排在路肩之上、路面之下**，所以河保持連續 |
| 顏色 | 散在 renderer 裡的 hex | 集中在 `mapVisualStyle.js`，含明度階序規則 |
| 自我檢查 | 做不到（沒有瀏覽器） | 新增 `tools/preview_moba_map.mjs`，在 Node 直接輸出俯視 PNG |

最關鍵的一項是第一列：以前「驗證講的地圖」和「畫面上的地圖」是兩份計算，這次統一了。

---

## 3. 三路怎麼正式化

- 每條路是 **三層帶狀地形**：路肩（土色，26 寬）→ 路緣（深褐，20 寬）→ 路面（亮沙，13 寬）。
  三層的寬度各自沿路做低頻變化，所以邊界是有機的，不是等寬硬線。
- **Mid** 路面加寬到 16，並多疊一條「路心亮帶」⇒ 成為整張圖最亮、最明顯的對角線。
- **Top / Bot** 沿地圖邊緣彎曲（這是 `gameData.js` 既有的路線，本次只做視覺加工）。
- 路的兩端各自**越過基地中心 6 單位**，所以路真的插進高地平台、接上三個出口坡道，
  不是停在基地外面。
- 18 座塔一律落在自己那條路的路面帶上（有驗證逐座檢查）。

---

## 4. 河道怎麼正式化

- 四層：河岸泥地（50 寬）→ 河床（38）→ 水面（29）→ 淺灘亮帶（12）。
  水色用低飽和灰藍 `#36657a`，不是塑膠亮藍。
- **圖層順序是這次最重要的一個決定**：河與 mid lane 幾何上必然交叉。第一版把河整體
  排在路之下，結果河被 26 寬的路肩截成兩段，完全讀不出「一條貫穿中段的河」。
  現在河排在「路肩之上、路面之下」⇒ 河保持連續，只有窄窄的路面像涉水點一樣跨過去。
- 河的兩端**收窄（taper 到 0.22 倍寬）**，不會被硬生生切一刀變成藍色長方形。
- 河把地圖切成上下兩半：藍方兩個野區在河的一側、紅方兩個在另一側。
- Dragon / Baron 各有一條**河灣（spur）**從河道最近點切進坑口，兩坑因此是「長在河邊」，
  不是浮在草地上的圓形標記。

---

## 5. 野區通道怎麼正式化

- `gameData.js` 只有 28 個牆點。本次把它們還原成 8 條牆鏈，每條經過
  **細分 → 擾動 → 逐段高低厚薄變化**，變成約 200 段短牆組成的弧形岩壁。
- 四個野區各有自己的草地色塊（明度略低於主草地，相鄰兩塊還交替不同綠），
  再加上幾個更暗的「樹叢暗斑」打破大片死綠。（**這只是地面色塊，不是 Bush / Tree Pack。**）
- 每個 camp / buff 外圍有一圈**口袋牆**，在朝向地圖中心與其反向各留一個開口
  ⇒ 形成「有入口、可繞行」的小空間，而不是四面封死或完全開放。
- Buff 的口袋半徑（17）比一般 camp（13）大，空間感更明確。
- 石頭只放在牆鏈端點與崖腳共 26 顆，不平均灑滿地。
- 有一條硬規則被驗證強制：**牆體不可以長在路面、河面或基地平台上**。
  （這條抓到了 7 段違規，已修掉；成因是禁區帶與路面帶用了不同的隨機相位。）

## 6. Dragon / Baron 怎麼正式化

兩坑主要靠**形狀**分辨，顏色只是輔助：

| | Dragon | Baron |
|---|---|---|
| 位置 | 下半區 | 上半區 |
| 坑半徑 | 17（較寬） | 14（較窄） |
| 開口角度 | 較大 | 較小（較封閉） |
| 坑壁厚度 | 5.2 | 7.4（更厚） |
| 坑壁高度 | 9.5 | 13.5（更高） |
| 輔助色 | 紫 | 琥珀 |

- 坑壁是**馬蹄形連續厚壁**（約 58 段），不是一圈正多邊形。
- 兩個入口的方向不是隨便給的，是取**河道在該處的切線方向** ⇒ 入口必然朝河道的上下游。
  驗證會檢查入口點確實落在河道帶內。
- 坑底做成大面積下凹深色，色環收得很細（只有半徑的 0.56~0.66 之間），
  避免又變回「圓形 UI 標記」。

## 7. 基地 / 高地怎麼正式化

- 平台不是圓盤，是 **三葉形**：朝三路方向各鼓出一個葉瓣 ⇒ 出口方向直接寫在輪廓上。
- 平台是有厚度的量體（extrude 3.6），外圍有 rim 牆，**三路方向留缺口**。
- 每個缺口對上一條**出口坡道**（平台面上的沙色道）與一組門柱，坡道往外延伸接上 lane。
- 平台半徑從 30 縮到 15：基地在地圖角落，再大就會被地圖邊界切掉、讀成「角落色塊」。
- 平台顏色改成**低飽和石材**（帶一點藍/紅），隊色只留給主堡晶體與塔冠
  ⇒ 基地讀起來是地形，不是一塊藍色 UI 區塊。
- 主堡 = 石座 + 隊色晶體；泉水 = 平台面上的發光圓台。

---

## 8. 塔點怎麼正式化

- 三個等級靠**底座大小 + 疊層數 + 總高**三件事一起區分，不只靠顏色：

| 等級 | 底座半徑 | 疊層 | 大約總高 |
|---|---|---|---|
| 外塔 | 5.0 | 2 層 | 中 |
| 二塔 | 6.2 | 3 層 | 高 |
| 高地塔 | 7.6 | 3 層（更粗） | 最高 |

- 每座塔地面有一塊深色八角底座色塊，所以從高空俯視也看得到塔的位置。
- 塔頂是隊色發光冠（藍/紅）。
- 這是 **placeholder**，不是 Tower Pack。

---

## 9. 仍然是 placeholder 的部分

1. **沒有任何貼圖**。全部是平面色塊 + `flatShading` 的低模量體。
2. **樹、草叢、地面細節不存在**。野區的暗斑只是地面顏色，不是模型。
3. **塔、主堡、泉水是幾何 placeholder**，不是正式建築模型。
4. **崖體是長方體堆出來的**，近看會看到方塊感；遠觀/俯視才成立。
5. **沒有陰影貼合**（`castShadow` 關閉，靠色階與方向光模擬立體感）。
6. **裝飾岩沿用既有 Rock Pack**，沒有新資產。
7. **手機視角只有推論、沒有實測**（見下方風險）。

---

## 10. 下一階段建議

依「投資報酬率」排序：

1. **先讓使用者目視定案構圖**。構圖若還要動，後面所有資產都要重做。
2. **Ground Pack**：地面現在是純色多邊形，最容易用一組 tileable 材質一次拉高質感。
3. **Bush Pack / Tree Pack**：野區的空曠感是目前最明顯的缺口，但要等構圖定案。
4. **Tower Pack**：塔的 placeholder 已經把三個等級的量體比例定下來了，可以直接照著做模型。
5. **正式 MobaView3D 接線**：目前只在 debug 預覽頁。接進正式戰鬥畫面前要先做效能實測。
6. **把 `preview_moba_map.mjs` 的俯視圖接成小地圖的資料來源**：同一份形狀資料，
   理論上可以直接產出 minimap，不必另外畫一張。
