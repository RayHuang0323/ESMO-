## §1 Audit 結論

（威脅感 ＋ 平衡一起量）與 `tools/check_combat_threat_l2.mjs`（行為驗證）。

### 1.1 塔：三個根因，都不是「傷害太低」

| # | 根因 | 證據 |
|---|---|---|
| ① | **塔挑小兵目標的 band 寫死 `0.05`，比小兵的攻城 band `minionSiegeBand: 0.06` 還窄** ⇒ 小兵打得到塔、塔打不到它 | 整場只有 **10 發**打小兵、353 發打英雄 |
| ② | **外塔離自己那條兵線最遠 5.94，射程只有 5.5** ⇒ 走在線上的英雄「明明在塔旁」卻永遠不在射程內 | `red_mid_0` 實測位移 5.94 > 5.5 |
| ③ | 塔傷**不執行擊殺**（保 Σk == Σd），且沒有連續命中懲罰 ⇒ 站著不會死，也不會越站越痛 | 英雄待在敵塔射程內 458 tick/場，殘血只占 11% |

**⚠ 這同時修正了 L Hotfix 1 的一個錯誤結論。** 上一輪說「一般車道塔沒有攻擊
小兵的程式碼路徑」——**那是錯的**。路徑在 lane 迴圈裡（`LogicEngine.js:2012-2030`），
我上一輪看到的 `continue`（`:2095`）是英雄仇恨迴圈裡的正常讓位。
真正的問題是那條路徑的 **band 太窄**，不是不存在。

### 1.2 龍 / 巴龍 / 野怪：會攻擊，但傷害等於沒有

| 對象 | 原值 | 對 400–960 HP 英雄的意義 |
|---|---|---|
| 龍 `dragonAttackDamage` | **1** | 每 1.35 秒 1 點 —— 完全沒有存在感 |
| 巴龍 `baronAttackDamage` | **1** | 與龍完全相同，看不出是更大的 Boss |
| 野怪 `campAttackDamage` | **4** | 前期也幾乎無壓力 |
| 野怪攻擊距離 | 2.35（仇恨 5.5） | 追過去也常常搆不著 |

另外發現一個**真缺口**：Boss 永遠鎖最近的英雄，一旦那個人被打到 1 HP 下限
（Boss 同樣不執行擊殺），`amount` 恆為 0 ⇒ **既不出手也不重置冷卻**，
之後整段站著不動。修正後「坑內有人卻沒反應」從 **521/761 → 7/761**。

### 1.3 一個測量教訓（本輪第二次踩到同一類坑）

`e.dragon` / `e.baron` 是 **v1/v2 的舊物件**（沒有 `pos`、`targetId` 永遠 null）；
v3 的 Boss 實體在 **`e.neutrals`**。第一版驗證讀錯物件，量出
「433 個存活 tick 一次都沒有目標」的假結論。
**先確認引擎狀態在哪個物件，再下結論。**

## §2 最終參數與理由

| 參數 | 原 | 新 | 理由 |
|---|---|---|---|
| `towerAggroRange` | 5.5 | **6.0** | 覆蓋外塔到兵線的最大位移 **5.94**（不是為了更痛，是為了讓「看起來在塔旁」＝「真的在射程內」）。debug 射程圈讀同一個值 ⇒ 視覺與邏輯必然一致 |
| `towerMinionBand`（新） | 寫死 0.05 | **0.10** | 必須 ≥ `minionSiegeBand`(0.06)，否則小兵打得到塔、塔打不到它 |
| `towerLockRamp`（新） | — | **0.10** | 連續命中同一英雄每發 +10% |
| `towerLockRampMax`（新） | — | **1.5×** | 上限溫和；塔仍不執行擊殺，改用「越站越痛」逼退 |
| `towerAggroDmg` | 66 | **66（未改）** | 根因不在單發傷害，不動它 |
| `minionTowerDmg` | 9 | **13** | 塔開始清兵後攻城壓力被吃掉，把節奏補回來 |
| `structureAccelT / Div` | 1200 / 180 | **960 / 130** | 用**既有的**後期收斂機制補回比賽長度，而不是把塔的正確修復削回去。只加速拆建築，不改擊殺、移速或任何傷害公式 |
| `dragonAttackDamage` | 1 | **26** | 約一名英雄最大生命的 3.5–6%，形成多人挑戰壓力而非秒殺 |
| `baronAttackDamage` | 1 | **44** | 明顯高於龍（1.7×）且間隔更短（1.05 vs 1.35） |
| `campAttackDamage` | 4 | **8** | 小野怪低至中等持續威脅 |
| `buffCampAttackDamage`（新） | — | **13** | Buff 野怪前期不能完全無壓力 |
| `campAttackRange` | 2.35 | **3.2** | 仇恨 5.5 卻只在 2.35 內打得到 ⇒ 追過去搆不著。仍遠小於仇恨距離 |
| Boss 目標選擇 | 最近 | **最近且還打得動** | 修「鎖到 1 HP 的人之後整段不動作」 |

**沒有使用極端數值**：塔的單發傷害一動未動；所有調整都對得回一個實測根因。

## §3 記分板 compact / expanded

新增 `src/battle/ui/hudStore.js`（極小的 `useSyncExternalStore`，不引入 zustand）
作為**高度的唯一來源**——記分板變矮之後，戰報與演出 callout 的安全區必須跟著變。

| | compact（預設） | expanded |
|---|---|---|
| 桌機高度 | **56px**（原 126） | 126px |
| 手機高度 | **48px**（原 126） | 118px |
| 內容 | 雙方比分、比賽時間、簡短隊名、勝率條 | 完整隊名、戰術標籤、塔數點陣、龍/巴龍倒數、MVP、勝率% |

- 兩個**固定檔位**，**沒有自由拖曳縮放**。
- 選擇存 `localStorage["esmo.hud.mode.v1"]`，live 與 Replay 讀同一個 store。
- **資料一筆都沒刪**，只調整資訊層級。
- 不影響 Timeline 的 hidden/compact/expanded（那是另一個獨立 store）。

六尺寸實測：compact 高度 ≤52（手機）／≤60（桌機）、戰報起點緊貼記分板底緣
（間距 ≤12px）、expanded ≤ viewport 20%、切換與持久化都正確。

## §6 已知限制與未驗

1. **「有 FX 沒掉血」殘留約 2%**（38 / 1750 發），實測**全部**發生在血量已低於 9 的
   英雄身上，是塔「不執行擊殺」下限與同 tick 治療／兩段式結算的邊界互動。
   **危險的方向（有傷害沒 FX）是 0。** 不為了讓數字歸零去動結算順序——
   那會改變所有 seed 且與本輪目的無關。已寫成有容忍度的斷言，不掩蓋。
2. **Boss 殘留 7/761 tick 沒反應**（修正前 521/761），落在死亡／重生交界。
3. **live 對戰的肉眼觀感未驗**（與 L / Hotfix 1 相同的環境限制）：headless 軟體渲染
   推不到英雄互毆階段。**塔與 Boss 打起來「痛不痛」需要 Ray 實際打一場確認。**
4. **真機未測**（Android / iOS）。桌面 headless 模擬**不等於**真機測試。
5. 既有紅燈 TD-21（陣列順序 20pp）未處理；本輪勝率位移 4.2pp 落在該噪音範圍內，
   無法從本輪資料區分兩者。

### 人工驗收重點（給 Ray）

- 站在敵方塔下 3–5 秒，血條是否明顯下降並越來越快。
- 走到龍／巴龍坑內，是否確實被攻擊、血條有反饋。
- 打野清 Buff 野怪時是否有壓力（不再是零風險）。
- 記分板 compact 是否夠讀、切到 expanded 是否資訊完整。
