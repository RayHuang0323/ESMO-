## 1. 目標 3：八個召喚師技能都有真實戰鬥效果

### 為什麼要另開一個 opt-in 層

引擎原本自己決定第二格：打野固定懲戒、其餘一律 `reserved`。要讓賽前配置生效，
就得讓外部資料決定引擎行為——這會改變模擬結果，而 `regress`／`runtime29`
的歷史基準全部建立在「沒有這一層」的行為上。

沿用本專案已有的三個 opt-in 行為層（`configureMatch` / `configurePlayers` /
`configureHeroes`）的同一套邊界，新增第四個 **`configureSpells`**：
**不呼叫 ⇒ 整段程式碼不存在。**

這不是宣稱，是量出來的：五個 seed 跑完整場比賽，比對「時間／勝方／每人擊殺／
金幣／血量」的完整摘要，**改動前後逐位元相同**（verifier §1–§4 每次執行都重驗）。

### 八個技能的實際效果

| 技能 | 觸發條件 | 實際效果 |
|---|---|---|
| 閃現 | 逃生／追擊收頭／切入團戰 | 位移（沿用既有，落點保證可走） |
| 懲戒 | 大型中立目標血量進入斬殺線 | 真實傷害（沿用既有） |
| 傳送 | 自己脫離戰鬥、我方某塔被 ≥2 人圍攻 | 傳送到該塔附近 |
| 治療 | 自己殘血且敵人在附近／隊友殘血 | 回復自身 16%＋隊友 10% 最大生命 |
| 護盾 | 血量 <34% 且敵人貼身 | 吸收 20% 最大生命的傷害，3.5 秒 |
| 點燃 | 射程內敵人血量 <50% | 每秒 26 點持續傷害 ＋ 回復量 −40% |
| 幽魂 | 追擊中，或撤退且殘血 | 移速 ×1.28，6 秒 |
| 淨化 | 身上有減速 | 解除並免疫 2.5 秒 |

`exhaust`（虛弱）**從技能表移除**：它沒有引擎作用點，留著就等於繼續做這個
Milestone 要消滅的事。輔助改帶淨化、刺客改帶幽魂，現在表裡**八個技能全部
`engine: true`**，不再有「圖示存在、引擎不認得」的組合。

### 三個實作上的判斷

1. **點燃是獨立傷害源，不是傷害乘數。** S28 §2 的紅線是「不得有東西乘進
   `dmgAmt = p.power * dt * …`」。點燃走自己的結算（`_igniteTickV2`），
   普攻公式一個字沒動。verifier §35 用行為驗證這件事。
2. **護盾走單一傷害出口。** 新增 `_damageHero()`，未啟用技能層時它就等於
   原本的 `foe.hp -= amt`（同一行）。不做這層抽象的話，兩個扣血點會各自
   長出一份護盾邏輯。
3. **懲戒歸屬由引擎裁決，不信任賽前資料。** 餵一份「中路帶懲戒、打野沒懲戒」
   的壞資料進去，引擎會把懲戒拔掉並補回給打野（verifier §16／§17）。
   Ray 要求「非打野不得自動取得 Smite」——最後一道防線放在引擎，不是 UI。

### 修掉一個施放不出來的 bug

傳送初版一次都沒放出來。條件寫成「沒有最近的敵人」，但**最近的存活敵人幾乎
永遠存在**，那個分支是死的。改成「身邊 18 單位內沒有敵人」之後正常觸發。

## 2. 目標 6：三處只認得兩個技能的地方

這三處在 J 之前都是**潛伏的錯誤**——第二格只可能是懲戒時剛好不會出事：

| 位置 | 舊行為 | 後果 |
|---|---|---|
| `battleEvents.js` | `spell === "flash" ? "閃現" : "懲戒"` | 治療／點燃／傳送**全部會被播報成「懲戒」**，而且 Replay 原封保存這串字 ⇒ 整場戰報說謊 |
| `BattleHeroStrip` 的 `SPELL_META` | 只有閃現與懲戒兩筆 | 其餘六個技能在十人面板畫成「?」 |
| `BattleHeroSheet` 狀態列 | 只認 `slow` | 護盾／點燃／加速看不到 |

三處都改成讀技能表（唯一命名來源）。記分板另外改成**優先讀引擎的技能欄**——
它帶著實際使用次數，Result 才答得出「這場放了幾次」而不只是「帶了什麼」。

### 開啟技能層之後的節奏（regress 沒有涵蓋的那條路徑）

`regress` 跑的是**沒有技能層**的基準。玩家實際走的正式對戰**會**開這一層，
所以 verifier §5 另外用同一組 15 個 seed 跑一次：

| 指標 | 基準（無技能層） | 技能層 ON |
|---|---|---|
| 結束率 | 15/15 | **15/15** |
| 平均時長 | 23.5 分 | **24.3 分** |
| 平均擊殺 | 29.8 | **34.5** |
| 零擊殺場 | 0 | **0** |
| 藍／紅勝場 | 10/5 | **10/5** |

擊殺數上升是點燃帶來的，符合預期。**陣營勝負分佈完全沒有位移**
（同一組 seed，兩邊都是 10/5）⇒ 這一層沒有破壞對稱性。10/5 的偏斜是
seed 變異，基準本來就是這個數字。

### 一條斷言我改了定義，講清楚為什麼

verifier §30 原本照抄 `regress` 的「瞬間 ≥8 人撤退」當死鎖判準，技能層開啟後
有 2 個 seed 命中。實測那 2 個 seed：**峰值 8 人（不是 10）、最長連續 2.5 秒、
整場合計 4 秒**——那是大團戰剛結束時的正常後撤，不是鎖死。

「撤退鎖死」的語意是**回不來**，所以判準應該是持續時間。§30 改成
「連續 30 秒以上 ≥8 人撤退」，另外新增 §30b 釘住「不得十人同時撤退」。
兩條都把實測值印在標籤上（目前 2.5 秒 / 峰值 8），不是藏起來。

**這是放寬還是修正？** 我的判斷是修正：原判準測不到它宣稱要測的東西。
但這是我的判斷，數據都在上面，Ray 可以推翻。

### 瀏覽器驗收驗的是「引擎真的動了」

`shot_milestone_j` 走完整條
Dashboard → Lineup → Matchmaking → Ban/Pick → Tactic → Loading → GameView →
Result → Replay，除了 I-close 的逐席比對，另外驗三件 J 專屬的事：

- **§13b** 對戰中面板兩格都顯示引擎狀態（「可用」或冷卻秒數），**沒有純「配置」佔位**。
  實測文字：桌機 `⚡ 閃現 可用 🌐 傳送 可用`、手機 `⚡ 閃現 可用 🎯 懲戒 54s`
  —— 傳送在 I-close 時是「配置」（無引擎效果），現在是真的技能。
- **§14b** Result 記分板帶實際使用次數，整場合計 **87（桌機）／76（手機）**。
- **§21** Timeline 的技能事件，**每一筆都必須是該席位真的帶著的技能**
  —— 這條專門照 `battleEvents` 那個「不是閃現就叫懲戒」的舊 bug。

證據：`evidence/{desktop,mobile}-0{1..6}-*.png` 十二張 ＋ `milestone_j_browser.json`。

## 6. 過程中兩次紅燈都是驗收腳本的問題（已查證）

1. **Timeline 抓不到技能事件**：首版取樣窗只有 12 秒，而第一顆懲戒約在
   60–90 模擬秒才出現。同一場的 Result 使用次數是 84 ⇒ 引擎有放，是取樣太短。
   把窗拉到 31 秒後桌機正常。
2. **手機仍抓不到**：手機版戰報**預設收合**（S29B2 的設計，避免遮住地圖），
   只顯示最新一則。加 `data-testid="timeline-toggle"` 讓腳本像使用者一樣先展開。

兩次都不是產品缺陷，也都不是靠放寬斷言解決的。
