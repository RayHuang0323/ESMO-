# 學習力・方案 B 測試規格（**僅規格，本輪不實作**）

## 0. 為什麼要換掉方案 A

方案 A（個人 `learning` → `xpRateScale` ＋ 隊伍平均 → `TEAM_LRN_XP`）在第一輪 512 場實測中
**所有行為指標皆為 0**：

| 指標 | 40 分 | 90 分 |
|---|---|---|
| 集火 | 0.0 | 0.0 |
| 技能放空率 | 0.0% | 0.0% |
| 無效攻擊率 | 0.0% | 0.0% |
| 補刀率 | 100.0% | 100.0% |
| 本場等級 | 9.06 | 9.01（**方向相反**） |

Δ勝率 +31.3pp 是雜訊（8 seeds 單格 95% CI ≈ ±26pp），不是效果——
行為完全沒變的情況下勝率不可能有因果性位移。

方案 A 的三個結構問題：

1. **語意重疊**：`xpRateScale` 實質是「吃線效率」，已由精準度／操作速度／專注力涵蓋。
2. **無法跨模式**：CS 沒有局內等級系統，`combatSkill` 是絕對值加權，A 在 CS 無處可掛。
3. **個人與隊伍重複計算**：同一個 `learning` 同時進個人項（0.005）與隊伍平均項（0.012）；
   天賦 `team_3` 與訓練課程「版本研究」會同時放大兩者。

---

## 1. 方案 B 的語意

**學習力＝在同一場比賽中修正自己失誤的速度。**

不改變「失誤率的起點」，只改變「失誤率隨時間下降的速度」。
第一分鐘完全沒有加成，越後期修正得越多，上限 2%–3%。

⇒ MOBA 與 CS 共用同一句話：MOBA 隨**比賽時間**遞減、CS 隨**回合數**遞減。

---

## 2. MOBA 側規格

### 2.1 掛在哪

沿用 P0-3 **既有的三個失誤係數**，不新增作用點：

| 係數 | 現況（`ONESIDED_CLAMP`） | 方案 B 的作用 |
|---|---|---|
| `castMiss` | penalty，上限 0.10 | 隨時間乘上衰減因子 |
| `attackWaste` | penalty，上限 0.08 | 同上 |
| `retreatLate` | penalty，上限 0.06 | 同上 |

### 2.2 公式

```
u(v)      = clamp((v − 70) / 30, −1, +1)          // 既有慣例
lrnU      = u(learning)                            // 個人層，**不取隊伍平均**
progress  = clamp(t / adaptFullT, 0, 1)            // t = 模擬秒；adaptFullT 建議 900（15 分）
adapt     = ADAPT_MAX × lrnU × progress            // ADAPT_MAX 建議 0.03
有效失誤率 = 既有失誤率 × (1 − adapt)
```

**中性檢查**：`learning = 70 ⇒ lrnU = 0 ⇒ adapt = 0 ⇒ 有效失誤率 = 既有失誤率`，
逐位元與現況相同。**這是必須驗證的第一條。**

**負向**：`learning < 70 ⇒ lrnU < 0 ⇒ adapt < 0 ⇒ 失誤率略升`（最多 +3%）。
低學習力＝越打越不會修正，語意成立。

### 2.3 刻意不做

- **不碰 `xpRateScale`**（方案 A 的路徑整條移除）
- **不改英雄等級曲線、不改 `p.power`、不改任何傷害公式**
- **不取隊伍平均**（避免方案 A 的個人／隊伍重複計算）

---

## 3. CS 側規格（本輪不實作，僅記錄語意）

掛在既有的 `combatSkill(p, opts)` 末端：

```
progress = clamp(roundsPlayed / adaptFullRounds, 0, 1)   // adaptFullRounds 建議 16
adapt    = ADAPT_MAX × u(lrn) × progress
combatSkill 回傳值 × (1 + adapt)
```

不改武器數值、不改 `GUNS`、不改傷害、不動 `aggr()`。

---

## 4. 驗證規格

### 4.1 必須通過的中性條件

| # | 斷言 |
|---|---|
| B-1 | `learning = 70` 時，`castMiss` / `attackWaste` / `retreatLate` 與現況**逐位元相同** |
| B-2 | 全 16 項 = 70 時，整場 snapshot digest 與現況逐位元相同 |
| B-3 | 未呼叫 `configurePlayers` 時完全短路（`regress` / `regress2` 不受影響） |

### 4.2 效果必須可觀測

| # | 斷言 |
|---|---|
| B-4 | 比賽前 2 分鐘：90 分與 40 分的三項失誤率差異 **< 0.5pp**（初期無加成） |
| B-5 | 比賽後段（>15 分）：90 分的失誤率明顯低於 40 分，且差距 **≤ 3%** |
| B-6 | 差距隨時間單調遞增（取 5 / 10 / 15 / 20 分四個切片） |

### 4.3 不得越界

| # | 斷言 |
|---|---|
| B-7 | `xpRateScale` 的 `STAT_MAP` **不含 `learning`** |
| B-8 | 本場等級（`mlv`）在 40 / 90 之間的差異 **< 0.1 級** |
| B-9 | P0-3 §4-2c（空揮 ≤ 8%）、§4-3c（技能差距 ≤ 10pp）仍通過 |
| B-10 | P0-3 §4-5c（等級差距 ≤ 2.5）**不受影響**——目前餘裕只剩 0.04，這是方案 A 最大的風險 |
| B-11 | P0-3 §4-6c（勝率 ≤ 85%）仍通過 |
| B-12 | 傷害公式 `dmgAmt = p.power * dt * R.dmgK` 未被動過 |

### 4.4 量測方式

沿用 `tools/measure_stat_sensitivity.mjs`，新增**時間切片**輸出：
在 5 / 10 / 15 / 20 分各取一次三項失誤率，比較 40 / 70 / 90。
30 seeds × 鏡像對跑；勝率只作旁證。
