## 2. 撤退／再投入模型的結構判定

### 2-1 問題

> 「高 decision / positioning → 更常撤退 → 少死 → 推塔下降」
> 是合理 trade-off，還是戰鬥 AI 的收益結構有問題？

### 2-2 判定：**收益結構有問題。這不是合理的 trade-off。**

三層證據，逐層排除「合理 trade-off」的解釋。

#### 層 1：跨素質，死亡與推塔是**同向**的

每一項素質各取一個點（Δ = 90 分減 40 分）做相關。
**兩種情境各自獨立達到顯著**：

| 相關 | 中性情境（r9gen，10 項） | **真實對局條件（r10_standard，12 項）** |
|---|---|---|
| **r(Δ死亡, Δ推塔)** | **+0.903** [0.632, 0.977] ★ | **+0.865** [0.579, 0.962] ★ |
| r(Δ撤退, Δ推塔) | −0.739 [−0.934, −0.204] ★ | **−0.830** [−0.951, −0.488] ★ |
| **r(Δ撤退, Δ推塔/作戰分)** | −0.760 [−0.940, −0.250] ★ | **−0.835** [−0.953, −0.502] ★ |
| r(Δ作戰持續, Δ推塔) | +0.677 [0.083, 0.916] ★ | +0.688 [0.189, 0.905] ★ |

**死得越多的素質，推得越多。** 若「少死 → 存活 → 再投入 → 推進」這條鏈成立，
這個相關應該是負的。它是強正相關，**且在兩種完全不同的 knob 條件下都成立**。

真實條件下 12 項的散佈（`Δ推塔/作戰分` 由負到正）清楚呈現同一條軸：

```
decision -0.187 │ positioning -0.167 │ tacticalIQ -0.107 │ focus -0.102
adaptability -0.078 │ accuracy -0.062 │ mapAware -0.055 │ reflex -0.036
                    ── 0 ──
resilience +0.018 │ apm +0.077 │ courage +0.169 │ clutch +0.218
```

#### 層 2：用「實際在場時間」正規化後，效果**不消失**

若撤退的代價只是「人不在場」，那麼用 `推塔 / (場長 × 作戰持續率)`
——真正在作戰的每一分鐘換到多少推塔——正規化後，差異應該被吸收掉。

| 素質 | `retreatAdj` | Δ撤退 | Δ死亡 | Δ推塔 | **Δ推塔/作戰分** |
|---|---|---|---|---|---|
| decision | +0.030 | **+26.0%★** | −19.6%★ | −12.1%★ | **−8.8%★** |
| positioning | +0.040 | **+14.5%★** | −21.3%★ | −11.6%★ | **−8.6%★** |
| focus | +0.020 | +5.9%· | −13.3%· | −6.8%★ | **−7.5%★** |
| mapAware | （無） | −3.1%· | −11.9%· | −7.0%★ | **−5.8%★** |
| adaptability | （無） | +10.4%★ | −6.6%· | −3.9%· | **−5.7%★** |
| **clutch** | **−0.040** | **−8.2%★** | **+38.4%★** | **+15.4%★** | **+10.1%★** |
| **courage**（invade, n=200） | **−0.050** | **−14.9%★** | **+29.2%★** | **+14.3%★** | **+11.3%★** |

**沒有消失。** 撤退方在場時也推得比較少 ⇒ 損失**不是**「人不在場」造成的。

雙向都顯著且對稱：`retreatAdj` 為正（更早撤）→ 推塔效率下降；
為負（撐更久）→ 推塔效率上升。這是乾淨的劑量反應，不是雜訊。

#### 層 3：撤退**回不來**——但只有謹慎那一側

`重返(扣死)/撤退`（已扣掉死亡造成的假重返）：

| 素質 | 40 | 90 | 配對 Δ | 顯著 |
|---|---|---|---|---|
| **decision** | 0.958 | 0.869 | **−9.4%** | ★ |
| **positioning** | 0.916 | 0.859 | **−6.3%** | ★ |
| **courage**（n=200） | 0.855 | 0.908 | **+6.1%** | ★ |
| clutch | 0.863 | 0.887 | +2.7% | · |
| 其餘 7 項 | — | — | 全部 <2% | · |

decision 每提高一級，**撤退次數增加 26%，但每次撤退換回的重返少 9.4%**。
撤退變得便宜（容易觸發），但**復原變貴**。

### 2-3 為什麼這不是「合理 trade-off」

合理的 trade-off 應該長這樣：謹慎方少死 → 存活時間換成推進 → 推塔持平或微降，
而勝率因為少送頭而上升。實際上：

- **少死是真的**：decision −19.6%★、positioning −21.3%★。
- **每次死亡的效率也真的變好**：decision 的 `推塔/死亡` +19.7%★、`K/D` +28.6%★。
- **但總量輸了**：推塔 −12.1%★，勝率 −17.4pp（30 seeds 不顯著，但方向明確；
  對照組 courage 在 n=200 時 **+11.3pp★ 顯著**）。

也就是說：**引擎確實獎勵存活（單位效率上升），但撤退這個動作本身的成本
大於它省下的死亡。** 存活的收益被撤退的成本吃光還倒賠。

層 0 的中性基準內相關（能力固定全 70，n=60）可以佐證死亡本身確實是有代價的：

```
r(死亡, 推塔/作戰分) = -0.381  [-0.579, -0.140] ★     ← 同一場裡，死越多推越沒效率
r(撤退, 死亡)        = +0.792  [0.674, 0.871] ★       ← 撤退與死亡機制上高度耦合
```

矛盾就在這裡：**死亡有代價（層 0），但能力層唯一能用來減少死亡的工具是撤退，
而撤退的代價更大（層 2、層 3）。**

#### 層 4：在**真實對局條件**下完整複製（獨立複驗）

§2 的層 1–3 全部來自 r9gen（中性情境）。在 `standard` 情境
（逐鍵＝正式 `toEngineTactic(STANDARD_OPP_TACTIC)`）重跑，同 30 seeds：

| 指標（配對 Δ，40→90） | decision 中性 | **decision 真實** | positioning 中性 | **positioning 真實** |
|---|---|---|---|---|
| 撤退 | +26.0%★ | **+37.7%★** | +14.5%★ | **+13.6%★** |
| 推塔 | −12.1%★ | **−10.8%★** | −11.6%★ | **−11.2%★** |
| **推塔/作戰分** | −8.8%★ | **−10.6%★** | −8.6%★ | **−9.7%★** |
| **重返(扣死)/撤退** | −9.4%★ | **−11.5%★** | −6.3%★ | **−7.7%★** |
| 作戰持續率 | −1.4%★ | **−2.5%★** | −1.4%★ | **−0.9%★** |

**每一項都複製了，且在真實條件下更強。** 這排除了「結論是中性情境的產物」這個可能性
（§1-3 指出中性情境關掉了六個作用點，但 `retreatAdj` 不在其中——撤退永遠生效）。

### 2-4 判定的邊界（誠實邊界）

- decision / positioning 的證據來自 r9gen（30 seeds、中性情境），
  並已在 `standard`（真實對局條件）下完整複製（層 4）。
  中性情境關掉了 decision 的 `roamGateAdj`，但**沒有**關掉 `retreatAdj`
  （撤退永遠生效），所以撤退鏈的結論不受 §1-3 的情境問題影響。
- 跨素質回歸（層 1）已在兩種情境下各自達到顯著（見 §2-2 層 1 的雙欄表），
  非單一實驗條件的產物。
- courage 的鏡像證據來自 invade 情境（n=200，CI 很緊），但該情境的
  `invadeChance 0.5` 高於真實值 0.1 ⇒ **方向可信，幅度偏大**。
- 「勝率」在所有 30/60 seeds 的格子裡都不顯著。支撐判定的是**行為鏈的一致性
  與雙向劑量反應**，不是任何單一勝率數字。
- `重返(扣死)/撤退` 的扣法是保守下界（假設每次死亡恰好一個假重返）。
  若實際上死亡有時不會清掉 retreating，真實跌幅會比 −9.4% 更大而非更小。

### 2-5 ⇒ 這不該用調權重來修

降低 `decision` / `positioning` 的 `retreatAdj` 只會把他們推向 clutch / courage 那一端
——變成「多死但多推」。那不是「決策力好」的語意，只是換一個方向錯。

**要修的是收益結構本身**（屬 `_postCombatV3` / 撤退狀態機那一層，本輪不修）：
撤退後應該要能把「保住的血量與經驗」換成後續的推進或視野收益，
而不是單純消失一段在場時間再回到原點。

## 3. 五個專屬情境的結果

### 3-1 invade（勇氣）｜100 seeds × 鏡像 = 每格 200 場

**接線正確**：入侵次數 0.475 / 0.535 / 0.585，配對 Δ **+0.110 ★**（CI [0.067, 0.153]）。

**但這個作用點沒有後果**：

```

有發生入侵的場次 319｜其中 invadeKills > 0 的場次 0
```

引擎裡入侵＝開局前 50 秒把打野（`invadeWithMid` 時加中路）的移動目標改成

拿到人頭時遞增（`:2433`）——**319 次入侵一次都沒發生**。

**courage 的實際效果來自別處**。同一素質在中性情境（`invadeChance = 0`，入侵完全關閉）
與 invade 情境（0.5）的行為鏈幾乎相同：

| | 中性（invadeChance 0） | invade（0.5） |
|---|---|---|
| Δ撤退 | −11.100 ★ | −11.680 ★ |
| Δ推塔 | +4.133 ★ | +4.305 ★ |
| Δ死亡 | +3.983 ★ | +3.305 ★ |
| Δ作戰持續 | +0.010 ★ | +0.011 ★ |

⇒ **courage 的效果幾乎全部來自 `retreatAdj −0.050`，不是 `invadeAdj`。**

⚠ 保留：invade 情境同時把 `gankInterval` 45→35，兩者不是單一變因對照，
勝率差（−0.3pp vs **+11.3pp ★**）不可歸因給入侵。但「319 次入侵 0 擊殺」與情境設計無關。

## 7-1 指標誤讀：`towerPushes` 不是推進強度

`LogicEngine.js:2389`：

```js
if (K && this.t - S.pushTick > 10) { S.pushTick = this.t; this.exec[p.side].towerPushes++; }
```

`S = this._tac[p.side]` ⇒ **隊伍層級**、**每 10 秒最多 +1**。
上限 ≈ 場長秒數/10（23 分鐘約 134，實測約 29 ⇒ 責任週期 22%）。
它量的是「**有多少個 10 秒窗口，這隊至少有一個人碰到塔**」——presence，不是輸出。
五人猛拆與一人慢磨，計數相同。

**撤退變多 ⇒ 同時在塔邊的人變少 ⇒ 計數器掉，但五人的 `p.twrDmg` 總和未必掉。**

⇒ 推進主 KPI 改為 **`p.twrDmg`（推進輸出）＋ 推掉的塔數（推進成果）＋ 主堡傷害**。
`towerPushes` 降級為 **「塔邊責任週期」** 診斷指標，引用時不得寫成「推塔／推進」。

| 高 decision / positioning 是否顯著降低真實推塔輸出？ | **否**。decision +3.5%·、positioning −2.8%· |
| 是否降低推進成果（推掉的塔／主堡傷害）？ | **否**，皆不顯著 |
| 是否降低目標控制？ | positioning **−17.4%★ 是唯一顯著項**；decision −12.6%· |
| 勝率是否有可解釋的因果鏈？ | **否**。四項撤退軸素質的勝率全部不顯著（含 decision −15.0pp） |

⇒ **`retreatAdj` 不再是競技平衡問題。**
唯一殘留的真實負面是 **positioning 的目標擊殺 −17.4%★**，
且它伴隨 **死亡 −18.8%★** ⇒ 是一個**可解釋的 trade-off**（更保守 ⇒ 少死、少搶目標），
不是斷裂的收益鏈。

### B. 行為品質 — **問題確實存在，但是對稱的**

| 指標 | 全部格子的範圍 | 判定 |
|---|---|---|
| 撤到泉水的比例 | **94.9% – 97.6%** | 幾乎每一次撤退都是整趟回家 |
| 撤退後重新產生貢獻 | **32.7 – 34.2 秒** | 離場成本高 |
| 撤退後零貢獻比例 | 3.1% – 4.8% | **低**——re-engage 確實會發生 |
| 15 秒內再次撤退 | 2.4% – 5.2% | **低**——不是反覆退進 |
| re-evaluate 狀態 | **不存在**（退出撤退是單一 HP 比較，無 timeout） | 結構性缺口 |

⚠ 但要注意「貢獻」的定義：95% 以上的撤退**會**產生某種貢獻（攻擊／推塔／目標），
其中大多數是**戰鬥**而非推塔。先前量到的「64.5% 沒再推到塔」只限「推塔」這一種貢獻。

**關鍵**：這些數字在 40 / 70 / 90 三格之間的差異都在 ±2pp 內
⇒ **撤退的離場成本是引擎對所有人一視同仁的固定成本**，雙方等價支付。
所以它拖慢節奏、看起來笨，但**不製造競技不平衡**。

### ⇒ 結論

> **retreatAdj：競技平衡問題 ✗、AI 行為品質問題 ✓。**
> 「AI 看起來笨」不等於「平衡有問題」——這一輪的整個教訓。

## 7-6 是否仍建議 `retreatReengageV1`

**建議：不做為平衡修正；可做為體驗改善，但優先序低。**

理由：

1. 競技層已證明無問題（§7-3 A）。做它不會改善任何真實 KPI。
2. 行為層的成本是**對稱**的——雙方等價支付，不影響勝負。
3. 若日後要做，成功門檻**不得**再用 `pushPerActiveCombatMinute`
   （分子是責任週期計數器）。應改用：
   `撤到泉水%`、`撤退後重新產生貢獻的秒數`、`撤退後零貢獻%`、
   以及真實產出 `twrDmg` / 推掉的塔。
4. 先前四次修正失敗的真正原因已查明：**目標本身是量測假象**，
   不是架構難修。

## 7-7 是否達到可封版狀態

**16 項素質影響盤點：可封版。**
- 16 項全部有作用點層級的因果鏈判定
- 8 項（撤退軸 4 + 指標敏感 4）已用真實 KPI 在真實對局條件下 30 seeds 重測
- 剩餘 8 項的判定不依賴已失效的指標

**待辦（不阻擋封版）**：
- adaptability / reflex / accuracy / comms / leadership / synergy / resilience / learning
  尚未用真實 KPI 在 standard 條件重測（其判定不依賴 `towerPushes`，但補測可提高一致性）
- F 類兩項（comms 的 `roamInfoAdj`、synergy 的分布飽和）是**下一輪**的實作標的
- 撤退行為品質改善（`retreatReengageV1`）列為體驗待辦，非平衡待辦
