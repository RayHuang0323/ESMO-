# 環境預覽 / 地圖裝飾放置工具（Environment Preview / Map Decor Placement Tool）— Milestone C

> 本文件用非工程師也看得懂的方式說明。**本次只做 debug 展示頁，未動正式遊戲流程、未動戰鬥模擬。**

## 0. 本階段定位（重要，先讀）

**Milestone C 的成果是「環境預覽／地圖裝飾放置工具」，不是「正式 MOBA 地圖完成」。**

1. **`terrain_style.glb` 是「環境美術與放置技術」的展示地形**（一塊峽谷／瀑布地形），
   用來驗證石頭放置、實例化、LOD、cull、乾淨預覽等**技術與工具**。
2. **它沒有正式 MOBA 的遊戲拓撲**：沒有上/中/下三路、沒有雙基地、沒有防禦塔、沒有四個
   野區象限、沒有龍坑（Dragon Pit）與巴龍坑（Baron Pit）。它只是單一地形展示，**不是
   ESMO 正式 MOBA 戰場**。
3. **可供正式地圖重用的技術資產**：Rock Pack、`mapDecorPlacement`（依地形分區放置）、
   `InstancedLODGroup`（實例化＋LOD＋cull）、`cameraPose`／乾淨預覽工具——這些**工具**在
   正式地圖上都能沿用。
4. **不再繼續把這張瀑布地形打磨成正式戰場。**
5. **下一階段（Milestone D）改為正式 MOBA Map Blockout**：依既有模擬座標建立三路／雙基地／
   河道／野區／龍坑／巴龍坑的遊戲骨架。

> 換句話說：Milestone C 交付的是「**能把環境資產放上任何地形的工具與預覽**」，不是「一張
> 可以打的 MOBA 地圖」。

## 1. 本次視覺改善目標

- **地圖不要空**：把上一階段做好的 8 件石頭，實際、合理地放進地圖（河岸、邊界、崖腳、
  野區），而不是只拿來壓測。
- **質感提升、不要太暗太灰**：把展示場景的光線與色調調得更暖、更亮、更好讀，讓俯視
  MOBA 視角下地形輪廓更清楚。
- **手機優先**：以中大型石頭為主、密度受控，避免太碎太高頻，手機上看得懂。
- **可維護**：這套「依地形分區放置」的做法，未來樹、草叢、地被都能沿用。

## 2. 使用哪些 Rock Pack 資產

沿用 Milestone B 的 8 件正式石頭（不新增資產）：小型 ×2、中型 ×2、大型 ×2、峭壁石、
河岸石。全部共用 1 個材質、各有 LOD0/LOD1、由既有 Environment Runtime 以 GPU 實例化放置。

## 3. 放置邏輯（怎麼決定石頭放哪）

地圖載入後，程式會「掃描地形高度」（對地形由上往下打射線取樣，建立一張高度圖），再依
**高度、坡度、離地圖邊界的距離** 把石頭分區放置：

| 分區 | 判定 | 用的石頭 | 目的 |
|---|---|---|---|
| **邊界（boundary）** | 靠近地圖邊緣、不在水裡 | 大石＋峭壁石 | 讓地圖邊界不空 |
| **河岸（riverbank）** | 水線略上方、坡度不陡 | 河岸石＋中小石 | 河岸有裝飾、有層次 |
| **崖腳（cliffbase）** | 陡坡面 | 峭壁石＋大石 | 銜接高低差 |
| **野區（jungle）** | 內陸平緩的場地/高地 | 中石為主成簇 | 破除「平面測試場」感 |

- **決定性**：用固定亂數種子（同 seed 產生完全相同的擺放），**不使用** `Math.random()`。
- **不重疊**：同類石頭保持最小間距（Poisson 取樣）。
- **效能友善**：每種石頭仍是一個 InstancedMesh（實例化），**draw call 不會隨石頭數量暴增**；
  地形只掃描一次、石頭只算一次，不每幀重算。

## 4. 地圖哪些區域被改善

- **邊界**：原本空蕩的地圖外緣，鑲上大石與峭壁石。
- **河岸**：沿水線鋪上河岸石與中小石，河邊不再是光禿斜坡。
- **崖腳／高低差**：陡坡處補上崖石，過渡更自然。
- **野區**：內陸平地補上成簇中石，不再像平面測試場。
- **整體色調**：展示場景改用較暖、較亮的光與 ACES 色調，背景由死黑改為藍灰天光，
  地形綠／褐／灰更協調、輪廓更清楚（此為**展示場景的呈現調整**，未改動地形模型本身）。

## 5. 效能影響

- **draw call 不隨石頭數量暴增**（架構保證）：8 種石頭 × 最多 2 個 LOD＝**最多 16 個
  draw call**，不論放幾百顆；遠處會被 cull，實際更少。加上地形，全場 draw call 仍在
  PERFORMANCE_BIBLE 手機 150 / 桌面 300 上限內。
- **材質 1、貼圖 0**（石頭全共用）；地形掃描與擺放只在載入時做一次，執行時不增加負擔。
- **FPS**：需**人工目視與瀏覽器確認**（本機無法自動量測真實 FPS，不虛構數字）。依 Milestone
  A/B 的同套 runtime 實測，同量級的實例化場景在桌面/手機皆維持約 60 FPS，預期本地圖整合
  不會明顯下降；實際請於 debug 頁確認。

## 6. 已知限制

- **FPS 未自動量測**：需人工在瀏覽器目視與確認（見第 5 點）。
- **野區石頭數量取決於地形**：野區只放在「內陸平緩」的地方；若該地形平緩內陸面積小，野區
  石頭會較少（屬正常、隨地形而定）。
- **未做「路徑旁碎石」的精準偵測**：目前沒有地圖的道路資料，故未針對路徑單獨放石；路徑感
  由野區與邊界石頭的分佈間接呈現。未來若地圖提供路徑資料，可再加一條「路徑」分區規則。
- **沿用 Milestone A/B 的兩點 Debug Benchmark 限制**（benchmark 假陰性、測試鏡頭距離造成
  mobile-low 全 cull）仍存在，屬 Debug 層、不影響本次視覺整合與正式遊戲。

## 7. 下一步建議

- **人工在瀏覽器確認視覺與 FPS**（步驟見下方「如何打開預覽頁」）；若滿意即可 commit。
- 之後做 **Tree / Bush / Ground Pack** 時，**沿用本次的「依地形分區放置」思路**：同樣
  `mapDecorPlacement` + 各自的 presets（換 assets 與 zone 條件），不需重寫放置系統。
- 若要更精準的路徑旁裝飾，未來可在地圖資料中提供道路曲線，加一條 path 分區規則。

## 如何打開預覽頁

1. `npm run dev`
2. 瀏覽器開 `http://localhost:5173/?debug=environment-runtime`（正式遊戲不加參數即可，
   完全不受影響）
3. 預設就是「**地圖視覺整合**」情境。右上面板可：
   - **鏡頭**：「俯視 MOBA」／「近檢視」切換
   - **顯示裝飾石**：勾銷可對比「原地圖」與「加石地圖」
   - **顯示地形**：開關地形
   - **Preset**：desktop／mobile／mobile-low（改變 LOD/cull 距離）
   - 面板即時顯示：instances、LOD0/LOD1、Culled、Draw Calls、Triangles、Materials、
     FPS、各 Rock 資產與分區數量
