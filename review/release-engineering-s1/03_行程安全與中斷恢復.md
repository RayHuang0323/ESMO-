### 兩種用法

| 用法 | 適用 | 身分檢查 |
|---|---|---|
| `createProcessRegistry({ taskId })` → `register(child)` → `terminate(pid)` | 新工具、Release Gate、run-gate、checkpoint runner | 登記時向 OS 查 PID、**OS 啟動時間**、命令列、工作區、任務 ID，寫進 JSONL（`<git common dir>/esmo-release-gate/processes/<taskId>.jsonl`）。終止前重查，啟動時間或命令列不同 ⇒ `pid_reused` 拒絕 |
| `terminateLiveTree(pid, { expectArgs })` | 手上有 `ChildProcess` 但沒有登記簿的舊呼叫端（harness、cdp） | 根行程必須在**目前這個 Node 行程啟動之後**才建立（使用者自己的 Chrome 一定更早 ⇒ `started_before_owner` 拒絕）；有 `spawnargs` 時命令列必須含啟動參數 |

### 兩者共通的規則

- PID 必須是 > 4 的整數，而且不是自己或父行程。
- 系統保護名稱一律拒絕：System、csrss、svchost、explorer、lsass、OneDrive 等。
- 後代先列出、後關閉：Windows 上結束父行程不會帶走子行程。
- 每一層都要求「子行程啟動時間 ≥ 父行程」，用來擋掉 PID 重用造成的假父子關係。
- 由葉到根逐一 `taskkill /PID x /F`，每次都再確認一次身分。
- 先正常關閉（graceful），等一段時間仍在才強制。
- **沒有**依名稱、依埠號、全部終止的 API；有測試掃過模組的匯出名稱。`listenersOnPort` 只做唯讀查詢（Listen 且 PID > 4）。

### Checkpoint 記錄的內容

- `manifest.json`（建立後不得修改，有 digest）：任務、候選 SHA 與 tree、測試工具的 sha256、事前登記契約的 sha256、環境（Node、平台，以及 `--env browser=…` 這類自訂項目）、執行程序（指令樣板、逾時）、案例清單、策略（per-case／per-unit）。
- `journal.jsonl`：只能追加，每一列都帶前一列的雜湊。事件包括 created、resume、session-start、case-done（原始資料 sha256）、case-failed（原因）、interrupted（原因）、unit-reset、complete（原始資料合計雜湊）。
- `raw/`：每次嘗試各存一份，**不覆寫**。

### 續跑前必須成立（否則 BLOCKED 或 FAIL）

- 候選 SHA 與 tree 相同。不同版本的結果絕不混在一起。
- 工具雜湊、契約雜湊、執行程序、環境都相同。
- journal 鏈完整：被刪掉一列或改掉一列都會 FAIL。
- 每個已完成案例的原始資料都還在，而且 digest 相同。
- 上一個 session 沒有正常結束時，自動記錄 `unclean-stop`。這涵蓋 Session 中斷、休眠和崩潰。
- **per-unit**（ABBA、同場對照、事前登記完整樣本）：沒有跑完的單位整組作廢重跑。舊資料保留，標記為 superseded。
- 每個案例記錄前，會重新確認工作目錄仍是同一個候選，避免別的 agent 中途切換 checkout。

### 用合成短測試驗過的情境

- 人工安全停止（`--stop-after`）。
- runner 被終止，模擬 Session 中斷、休眠或崩潰；終止的是登記過的測試行程。
- 瀏覽器崩潰（exit 3）、逾時、記憶體不足（依 exit 137 或訊息分類）。
- 原始資料被改或被刪、journal 被刪掉或改掉一列。
- SHA、工具、契約、瀏覽器版本、執行程序不同。
- 執行中工作目錄被改。
- per-unit 不完整時整組重跑。
- 不能重複計算、不能記錄未登記的案例、`raw/` 以外的檔案不能當原始資料。

### 限制

- 本輪只把 checkpoint 接進通用 runner 和 Release Gate 收據，**沒有**改造 P2v2、四引擎或 browser_all。
- 那些工具有事前登記的契約和雜湊釘死的程式，改造它們需要另外登記並得到 Owner 同意。
