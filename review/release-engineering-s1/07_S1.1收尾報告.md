防護：
- 分類一律由分類表依 **gate 名稱＋收據裡的實際指令** 重算；收據自己寫的分類不採信（偽造 ⇒ FAIL）。
- `--category` 與分類表不同 ⇒ FAIL；`--max-age-hours` 只能縮短。
- 舊收據（沒有 policy 欄位）一律 24h，不會因為分級上線而延長或重新生效。
- 分類表改動要升版；收據記錄的分類表摘要不同 ⇒ 退回 24h。
- docs-carry 的到期＝被沿用的來源收據依分類表算出的最早到期，不延長；不能連鎖沿用。

## 四、安全性審查（行程管理第二輪，Phase E）

「比本行程晚啟動」不再單獨足夠。現在的規則：
1. 登記 `ChildProcess` 時，OS 回報的父行程必須正是本行程；只給 PID 要附命令列比對。
2. `terminateLiveTree`（harness、cdp、舊 gate 的 preview）：根行程的父行程＝本行程、在本行程之後啟動、命令列符合啟動參數。使用者在測試開始後才開的 Chrome 父行程是 explorer ⇒ 拒絕。
3. 多個 Session／AI：登記紀錄帶擁有者。別的 Session 還活著 ⇒ 拒絕；前一個 Session 遺留 ⇒ 預設只回報，明確 `allowStale` 才清理（仍重驗身分）。
4. 祖先鏈（父、祖父…Claude Code、終端機）一律不終止。
5. 查身分到終止之間的競態：Windows 改成一次 PowerShell「開控制代碼 → 驗啟動時間與命令列 → 同一控制代碼終止」。持有控制代碼期間 PID 不會被重用。非 Windows 沒有 pidfd，仍是「重驗後立刻 SIGKILL」（殘餘風險，已記錄）。

所有危險反向案例只用假 OS 探針；真實終止只對測試自己啟動的無害 node 子行程。每輪測試前後都確認 Owner 的 Chrome 主行程（2026-11-25 23:12 啟動）仍在。
