## 3. 已知的依賴缺口（凍結時的狀態，沒有修）

盤點工具：`node tools/audit_semantics_deps.mjs`（唯讀；Opus 5.5 依規格撰寫，我審查後執行）。

| 項目 | 數字 |
|---|---|
| 語意清單 | 50 支 |
| `KNOWN_TRANSITIVE_GAPS` | 6 支，都還在、都還被 import |
| 從語意清單與引擎出發的 import 閉包 | 94 支 |
| 閉包裡、但兩份清單都沒有的 | 42 支 |
| 其中從 `src/LogicEngine.js` 直接走得到的 | **22 支** |

那 22 支（改了會影響對局，但指紋不會變）：

- 裝備：`items/` 下的 `combatStatsV1`、`itemCatalog`、`itemEconomy`、`itemEffectKeys`、`itemEffects`、`itemInventory`、`itemRecipes`、`itemsEngineRuntime`。
- 地圖幾何：`map/` 下的 `mapBaseBlueprint`、`mapBaseFrame`、`mapBaseLayoutStyle`、`mapBushCover`、`mapCampLayout`、`mapLaneStyle`、`mapMonsterShapes`、`mapShapePrimitives`、`mapTowerLayoutStyle`、`mapVisualStyle`、`mapZones`、`riftLaneClearance`、`riftLayoutGeometry`。
- `platform/contracts/tacticalDirective.js`：經 `tacticalDirector.js` import。版本檔的註解寫明它只供契約視圖用、不在引擎熱路徑，G-AC2 的 S6 會擋引擎呼叫 `directive()`。所以這一支是「已知而且有守門」。

其餘 20 支只從語意清單裡的其他檔案（組裝器、解析器、Challenge 等）走得到，包含 `featureFlags.js`、選手天賦與狀態、`playerModel.js` 等。盤點是用 import 的正則掃描，註解裡的 import 也會算進去，所以這個數字偏多不偏少。

**處理方式：**

- v23 這一側：用 F3 把那 22 支的內容釘住。不改指紋、不改清單。
- 要不要把它們補進語意清單：這會改變指紋的算法，等於一次重新登記。**獨立列案**（見 `驗證可靠性盤查.md` 案 2），放在 v24 候選第一次登記指紋時一起做，不回頭動 v23。
