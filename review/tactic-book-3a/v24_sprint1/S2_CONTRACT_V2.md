# S2 新契約 `s2.v2`（Owner 2026-11-19 核准）

> **適用範圍**：只用於事前登記過的驗證。舊 S2（「至少一次帶隊者到營地 ≥ 0.8」）一字不改，**舊 FAIL 維持，不回頭改判**。
> 判定工具：`tools/owner_preview/judge_s2_contract_v24.mjs`。契約函式：`tools/owner_preview/s2_contract_v2.mjs`。Gate：`tools/check_s2_contract_v24.mjs`。

## 1. 三項指標的狀態

| 指標 | 問的問題 | 狀態 |
|---|---|---|
| **S2-A 入侵執行率** | 決定出發之後，有沒有真的走到營地？ | **正式判準** |
| **S2-B 有效機會利用率** | 真正的好機會，有沒有被用上？ | **只報**，判定器驗證通過前不設門檻 |
| **S2-C 戰術活躍度** | 戰術有沒有實際在執行，既不是幾乎不動，也不是過度出發？ | **正式判準** |

## 2. 共同規則

1. **分母不能縮小**：分母是所有有入侵意圖的邊×場。沒出發的邊×場留在分母，不能剔除。
2. **工具與生涯分開**：兩條路徑各自判定。工具遇到混合路徑的資料會直接拒絕，輸出裡沒有合併數字。
3. **事前登記**：只有登記檔列出的資料組才會得到 PASS／FAIL。回看舊資料一律輸出 `NOT_JUDGED`。
4. **三項一起看**：只挑安全場次出發可以拉高 S2-A，但 S2-C 會下降。

## 3. S2-A 入侵執行率

- **定義**：帶隊者到營地的次數 ÷ 出發次數。單邊的到場數不會超過出發數。
- **區間**：以 Seed 為叢集的百分位 bootstrap，4,000 次，固定亂數種子。

| 結論 | 條件 |
|---|---|
| **PASS** | 出發 ≥ 60 次，95% 區間下界 ≥ 0.65 |
| **FAIL** | 出發 ≥ 60 次，95% 區間上界 < 0.65 |
| **INCONCLUSIVE** | 出發 < 60 次，或區間跨過 0.65 |

## 4. S2-C 戰術活躍度

- **C1**：每邊每場平均出發次數。
- **C2**：至少出發一次的邊×場比例。

| 結論 | 條件 |
|---|---|
| **PASS** | 0.6 ≤ C1 ≤ 1.5，而且 C2 ≥ 0.5 |
| **FAIL** | 其他 |
| **INCONCLUSIVE** | 沒有資料 |

Owner 核准的文字是平均值與比例本身的門檻，所以用點估計判定。區間會列出來，但不影響判定。

## 5. S2-B 有效機會利用率（只報）

- **判定器 v1**：O1 營地活著、O2 打野能出發、O3 到得了、O4 搶得贏、O5 沒有物件衝突、O6 值得。條件定義見 `tools/owner_preview/lib_s2_oracle_v24.mjs`。
- **報告項目**：每邊機會段數、整場沒有機會的邊×場比例、利用率（同目標、任一目標）、精確率。
- **隱藏資訊**：判定器讀完整真實狀態，只當離線評估標籤。它在 tick 之後才讀取引擎，不寫入任何欄位，AI 決策讀不到。Gate 用整場串流雜湊驗證對局不受影響。

### 判定器驗證

先回答「判定器標成機會的出發，實際結果有沒有比較好」，才討論要不要設門檻。

| 結論 | 條件（工具與生涯分開） |
|---|---|
| **VALID** | 機會內出發 ≥ 30 次，搶營率差與 60 秒金錢差的 95% 下界都 > 0，帶隊者陣亡率差的上界 ≤ +5 個百分點 |
| **INVALID** | 機會內出發 ≥ 30 次，搶營率差或金錢差的上界 < 0，或陣亡率差的下界 > +5 個百分點 |
| **INCONCLUSIVE** | 其他 |

就算驗證結果是 VALID，S2-B 也要等 Owner 另外核准門檻，才會變成正式判準。

## 6. Gate 守住的事

`tools/check_s2_contract_v24.mjs` 驗證：

- S2-A、S2-C 的每一條門檻邊界
- 沒出發的邊留在分母，沒有入侵意圖的邊不計入
- 工具與生涯不能合併
- 回看舊資料不給判定
- 舊 S2 的判定工具與舊結論沒有變動
- 掛上量測後對局逐 tick 相同
- 移動看不見的敵人，S11 特徵完全不變
