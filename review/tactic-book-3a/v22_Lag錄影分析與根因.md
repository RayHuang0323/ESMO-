## 結論

**Owner 的 Chrome 關閉了「使用圖形加速功能」，所以 3D 畫面全部由 CPU 用軟體繪製**（WebGL renderer＝`Microsoft Basic Render Driver`，也就是 Windows 的 WARP 軟體光柵器），沒有用到 AMD 顯示晶片。

- 同一台電腦、同一個預覽、同樣全螢幕 150% 縮放，用 AMD 顯示晶片時是 **59.3 fps**；改成軟體繪製就是 **4.8 fps**，和錄影一致。
- 舊版（正式站）在同樣的軟體繪製下也是 **4.8 fps**。新版戰術沒有造成這個 Lag。

## A. 錄影中觀察到的異常

做法：用 ffmpeg 解出全部 1,205 幀，逐幀比對前後兩幀的像素變化（地圖區、比賽時鐘、小地圖、滑鼠所在區分開算），並讀每一幀的容器時間戳。

## B. 錄影可以證實的 vs 推測

**錄影可以證實**

1. 錄影本身沒有掉幀：容器時間戳 92% 是 33 ms，最長 200 ms，而且滑鼠游標在 3D 畫面完全靜止的那些幀裡**逐幀移動**（例如 9.0 秒起第 54～59 幀）。所以凍結是瀏覽器畫面本身沒更新，不是 oCam 沒錄到。
2. 3D 畫面每秒只更新 3～8 次（數據見上表）。
3. 2× 時遊戲時間只跑約 1×。
4. 錄的是 `127.0.0.1:5642`，也就是上一輪改善後的打包版。用的是 Owner 平常的 Chrome（約 20 個分頁），全螢幕，同時在錄影。

**用其他方法證實（不是從錄影）**

5. Owner 的 Chrome 用軟體繪製：
   - 在 Owner 的 Chrome 開一個空白分頁讀 WebGL renderer，結果是 `ANGLE (Microsoft, Microsoft Basic Render Driver … D3D11)`。只讀，讀完就關了，沒有開對戰，也沒有動存檔。
   - Chrome 的 GPU 行程啟動參數是 `--use-angle=d3d11-warp-webgl`，最近崩潰次數 0。
   - Chrome 設定檔（`Local State`）裡 `hardware_acceleration_mode.enabled = false`，上一次啟動時也是 false。
   - Windows 的 AMD Radeon 驅動狀態正常（Status OK），顯示 1920×1080，系統縮放 150%。
6. 重現：用軟體繪製模式啟動的 Chrome、同樣全螢幕、同樣 DPR 1.5，數字與錄影一致（見 D）。

**仍是推測**

- 硬體加速是什麼時候、被誰關掉的：設定檔沒有時間紀錄，查不到。
- 錄影時「低」畫質只有每秒 6～8 次，我重現是 11.3 fps。差距推測來自 oCam 同時用 CPU 編碼 1080p 影片，以及 20 個分頁，沒有量。

## C. 新版戰術有沒有造成效能或更新問題

**沒有找到證據。**

- 模擬每個 tick 的執行時間（直接包住遊戲的 `setInterval` 量）：
  - 新版：平均 3.2～4.5 ms，最長 12 ms
  - 正式站舊版：平均 4.3～5.1 ms，最長 16.5 ms
  - 新版沒有比較慢。Tactical Director、入侵、Buff 修正都在這個 tick 裡，影響不到每幀 200 ms 的量級。
- **2× 只跑 1× 的原因不是模擬算不完**：每個 tick 只要約 4 ms，但 tick 排定的時間到了卻輪不到執行。主執行緒被每幀約 200 ms 的軟體繪製佔滿（忙碌 100%），tick 中位數晚到 185 ms。30 秒內只跑了 67 個 tick（2× 應該 120 個）。
  - 舊版一樣：晚到 169 ms、69 個 tick、遊戲時間 1.14×。
- 速度倍率與導播的程式在新舊版之間沒有差異會造成這個現象：同條件下舊版的表現相同。

## E. 最可能的根因與證據

**根因：Owner 的 Chrome 關閉了硬體加速，WebGL 改由 CPU 軟體繪製。**

證據鏈：

1. 設定檔 `hardware_acceleration_mode.enabled = false`。
2. GPU 行程參數 `--use-angle=d3d11-warp-webgl`。
3. WebGL renderer 是 `Microsoft Basic Render Driver`。
4. 用同樣的軟體繪製重現：高畫質 2× 是 4.8 fps、每幀約 200 ms、遊戲時間約 1×。錄影的更新間隔 166～366 ms、遊戲時間約 1×，兩者吻合。
5. 換成顯示晶片：同一個版本 59.3 fps、遊戲時間 2×。
6. 舊版在同樣條件下一樣卡 ⇒ 不是新版引起。

## F. 建議

### 1. 立即：Owner 打開 Chrome 的硬體加速（不用改程式）

1. Chrome 網址列輸入 `chrome://settings/system`。
2. 打開「**使用圖形加速功能 (如果可用)**」。
3. 按「重新啟動」。
4. 驗證：網址列輸入 `chrome://gpu`，「WebGL」應該顯示 `Hardware accelerated`。或者請我再讀一次 renderer，應該變成 `AMD Radeon(TM) Graphics`。

我沒有替你改這個設定，因為這是你的瀏覽器設定。

⚠ 如果當初是因為顯示晶片出問題（例如之前遇過的顯示記憶體耗盡、畫面全黑）才關掉的，打開後要留意是否復發。目前 Windows 顯示 AMD 驅動狀態正常，而且我自己啟動的 Chrome 用 AMD 顯示晶片跑完整場對戰沒有問題。

### 2. 小的程式修正（需要你核准才做，不改模擬語意）

在對戰載入時檢查 WebGL renderer。若是軟體繪製（`Basic Render Driver`／`SwiftShader`／`llvmpipe`）：

- (a) 在對戰畫面上方顯示一行提示：「瀏覽器未啟用硬體加速，畫面會非常卡；請到 Chrome 設定開啟『使用圖形加速功能』」。
- (b) 是否要同時自動降到「低」畫質？這會降低畫質，所以由你決定。

量測依據：「低」在軟體繪製下是 11.3 fps，遊戲時間能維持 2×；「高」只有 4.8 fps。即使降畫質，軟體繪製下仍然不順，提示比降畫質重要。

約 40 行，只動呈現層。

### 3. 執行期診斷（若打開硬體加速後仍然覺得卡）

在網址加 `?perf=1` 時，在對戰畫面角落顯示一個小面板：

- WebGL renderer 名稱
- 即時 fps 與最近 5 秒的最長幀
- 主執行緒忙碌程度
- 模擬 tick 晚到多少
- 遊戲時間／真實時間比例

你在同一場對戰就能看出卡頓來自畫面繪製（fps 低）、還是模擬（tick 晚到但 fps 正常）。量測方式與這次的工具相同；只在加參數時掛載，正式玩家看不到。也要你核准才做。
