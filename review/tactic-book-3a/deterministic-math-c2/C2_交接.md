## How det.v2 works (read before touching any of these files)

- `src/battle/moba/sim/simMathContext.js` holds the current simulation-math kernel, which is native by default.
  - A det.v2 engine is built with `new LogicEngine(seed, loadout, { mathKernel: "det.v2" })`. The assembler does this only for `L.mathKernel === "det.v2"`.
  - Its constructor and its 16 public entry points (configure*, tick, snapshot, frontTower, laneCleared, frontStructure, towerRange) re-enter `withSimKernel`.
  - `_simKernel` is non-enumerable, so it is not in any state digest.
  - The guard is `this._simKernel?.det` on purpose: diagnostics build engine views with `Object.create(LogicEngine.prototype)`.
- Kernel-aware shared code goes through the context:
  - `gameData` dist/posOnLane/laneLength (det.v2 lane-arc table built lazily)
  - `mobaTowerPlacement` and `mobaNavigation` (caches keyed by `simKernelId()`, det DIR16 from DetMath.v1)
  - `tacticExecV24`, `itemsEngineRuntime`
- **The native branch is the original expression, verbatim.** Any change there alters v20–v25. The v25 golden (`check_c2_v25_golden`) and the v20–v24 golden (`check_c1_legacy_golden`) will catch it.
- v18 map modules still use native trig at assembly. Under det.v2 the simulation-facing geometry is identical on 4 engines today (`check_c2_geometry --kernel=det.v2`), but nothing in the spec guarantees it (TD-TAC-65).
