## 1. 數學核心 det.v2 的定義

`det.v2` = DetMath.v1（`src/battle/moba/sim/detMath.js`，與 `eb28fbb9` 逐位元相同）+ DetHypot.v1（`src/battle/moba/sim/detHypot.js`）。

- **DetHypot.v1 的計算方式**
  - 採用 fdlibm 5.3 `e_hypot.c` 的結構：令 |x| ≥ |y|，極大或極小輸入先做精確的 2 的冪次縮放。
  - a² + b² 由可精確表示的部分乘積重組，切分高低位時用 Dekker 乘以 2^27+1。
  - 只用 `+ − × ÷`、正確捨入的 `Math.sqrt` 與 `Math.abs`。ECMAScript 不允許 FMA 合併，所以各引擎結果應該相同。
  - **沒有**使用容易溢位或下溢的簡單平方和公式。
- **特殊值**：照 ECMAScript 的規則。
  - 任一參數為 ±∞ ⇒ +∞（即使另一個是 NaN）。
  - 否則任一參數為 NaN ⇒ NaN。
  - hypot(±0, ±0) = +0。
- **使用範圍**：只在 det.v2 引擎執行期間使用（`src/battle/moba/sim/simMathContext.js` 的動態範圍）。
  - 涵蓋 `gameData` 的 `dist`／`posOnLane`／`laneLength`、塔位、導航、戰術執行、道具距離，以及 LogicEngine 的 hypot。
  - 原生核心仍是原本的 `Math.hypot`。
- **不在範圍內**：地圖幾何模組（`mapTerrainShapes`、`mapTowerLayoutStyle`、`mapBaseFrame` 等）完全不改，v18 凍結。

## 2. DetHypot 精度與極端值契約（H1～H8）

### 參考值與輸入

- **參考值**：`tools/lib/det_hypot_ref_c2.mjs`，只用 BigInt 整數運算。
  - x、y 換到共同的整數網格，算出精確的 X²+Y²。
  - 開根號時多保留 80 個小數位。
  - 以真值的 ulp 為單位；低於最小正規數時，ulp 以 2^-1074 計。
- **向量**：全部用 xorshift32 產生，正式種子 7201～7206（C1 用的是 7101～7105）。
  - 每一類的種子與抽樣方式寫死在 `tools/lib/det_hypot_vectors_c2.mjs`，在量測前提交。

### 契約條目

| 編號 | 類別 | 輸入 | 通過條件 |
|---|---|---|---|
| H1 | 遊戲範圍 | 種子 7201：x、y 均勻取自 [−1024, 1024]，20 萬組；種子 7202：近似相等（y = x·(1 ± 1e-6 內的亂數)），20 萬組；種子 7203：絕對值 ≤ 1024 的整數對，20 萬組 | 每一組誤差 **< 1 ulp**；另報平均值 |
| H2 | 寬範圍 | 種子 7204：指數均勻取自 [−1000, 1000]、正負號隨機，20 萬組 | 每一組誤差 < 1 ulp；沒有 ∞；非零輸入不得得到 0 |
| H3 | 極小／次正規 | 種子 7205：\|x\|、\|y\| ∈ [2^-1074, 2^-1000]（含次正規），10 萬組 | 誤差 ≤ 1 ulp（ulp 下限為 2^-1074）；非零輸入不得得到 0 |
| H4 | 極大 | 種子 7206：\|x\|、\|y\| ∈ [2^1000, MAX]，10 萬組 | 精確值 < MAX ⇒ 必須有限且誤差 < 1 ulp；精確值 > MAX·(1+2^-53) ⇒ 必須是 +∞；兩者之間的邊界帶照實回報 |
| H5 | 特殊值表 | 固定 36 組，例如 (±∞, NaN)、(NaN, ±∞)、(NaN, 1)、(±0, ±0)、(−0, −7)、(MAX, MAX)、(MAX, 1)、(5e-324, 5e-324)、(3·2^-1074, 4·2^-1074)、(3·2^1000, 4·2^1000)、(3, 4)、(−5, 12)、(1, 2^-60)、(1, 2^-27) 等 | 每一組都等於表中寫死的期望值（用 Object.is 比較；NaN 對 NaN） |
| H6 | 對稱性 | H1、H2 的全部向量 | hypot(x,y)、hypot(y,x)、hypot(−x,y)、hypot(x,−y) 逐位元相同 |
| H7 | 遊戲範圍精度不得變差 | H1 的向量 | DetHypot 的最大誤差 ≤ 同一組向量上 Node 原生 `Math.hypot` 的最大誤差；兩者的平均值都要回報 |
| H8 | 跨引擎 | H1～H6 全部向量（共 106 萬組以上）在 Node、Chrome、Firefox、WebKit 的輸出 | 四個引擎的輸出雜湊完全相同；任一引擎出現其他引擎沒有的 ∞／0／NaN 即 FAIL |

- DetMath.v1（三角函數／次方）沿用 C1 精度契約 v2 的 PASS 結果，不重跑。
  - 條件：`detMath.js` 必須與 `eb28fbb9` 逐位元相同（`git diff eb28fbb9 -- src/battle/moba/sim/detMath.js` 為空）。
  - C1 精度契約 v1 的 FAIL 紀錄保留，不重新判定。
- 判定工具：`tools/check_det_hypot_c2.mjs`。Node 部分跑 H1～H7；`--engines` 會在三個瀏覽器上重算 H8。

## 3. 效能門檻

- **環境**：同一台機器（AMD Ryzen 5 5600U，12 執行緒）、同一個 Node（v24.18.0）、單一行程，量測期間不跑其他重負載。

  - 只計 `engine.tick()` 的時間，組裝和雜湊不計。指標是每 tick 毫秒數。

  1. 3 輪的中位數 `v26 / v24 − 1 ≤ 10%`（相對現行原生核心）。

- **另行回報、不納入判定**
  - DetHypot 與原生 `Math.hypot` 的微基準。
  - 正式四引擎執行時，各瀏覽器的每場耗時。
- 注意：三種規則集在同一個種子下的比賽走向不同（勝負與長度都可能不同），所以比的是每 tick 平均成本，不是整場時間。

## 4. 正式四引擎驗證

計畫檔是 `C2_crossengine_plan.json`，與本文件一起提交。

- **種子**：261001～261080，共 80 場，都從未用過。
  - 登記時對整個 repo 執行 `git grep -w`，在 tools、review、src、docs 都是 0 筆。
- **對戰組合**：第 i 場（i = 0..79）為：
  - 種子 `261001 + i`，設定 `standard`
  - 藍方 `TACTIC_TEMPLATE_LIST[(3i+1) % 21]`
  - 紅方 `TACTIC_TEMPLATE_LIST[(7i+4) % 21]`
  - 與 C1 的規則相同，只換種子。規則集 `balanceTool.v26`，環境 `parity`，陣容用 `mirroredRoster(seed)`。
- **比對方式**
  - 同一份 MatchSetup JSON：同種子、同初始狀態、同規則集、同 RNG。
  - Node 是基準，Chrome、Firefox、WebKit 各跑一次。
  - 每個 tick 都比較整場引擎狀態的雜湊（`tools/c1/c1_state_digest.js`，所有自有欄位、數字的精確文字表示、FNV-64，**不排除任何欄位**）。
  - 也就是說，勝方、結束時間、事件、英雄位置、塔座標、兵線、經濟都在比較範圍內，判定檔另外逐項列出這些欄位。
- **重現性**
  - 前 8 場在每個引擎（含 Node）各再跑一次，兩次逐 tick 相同才算通過。
- **判定**
  - **PASS** 需要同時成立：
    - Chrome 80/80、Firefox 80/80、WebKit 80/80 都與 Node 逐 tick 相同。
    - 四個引擎的重現性都是 8/8。
    - 沒有缺漏。
  - 任一引擎未達 80/80，整體即為 **FAIL**。
  - 引擎無法執行、當機或缺場一律記為該引擎未通過，**不得**用 Chrome 的結果代替 Firefox 或 WebKit。
  - WebKit 是 Playwright 在 Windows 上的 WebKit 26.6，**不是** iOS Safari 實機認證。
- **候選凍結**
  - 正式執行前，先提交凍結候選，並在 `simulationVersion.js` 登記 v26 指紋。
  - 正式執行的每一筆紀錄都要帶 HEAD、`src` 是否乾淨、指紋。執行時如果 `src` 不乾淨或指紋不符，該次結果作廢。
- **工具**
  - 執行：`tools/c1/run_c1_crossengine.mjs`，加 `--plan=<C2 計畫>`、`--kernel=det`、`--url=http://127.0.0.1:5648/ESMO-/`。
  - 判定：`tools/c2/judge_c2_crossengine.mjs`，包含重現性的判定。
