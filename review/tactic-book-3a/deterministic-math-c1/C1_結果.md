### 2.2 正確性（與數學參考值的誤差）

參考值：`tools/lib/det_math_ref_c1.mjs`，BigInt 定點（≥ 256 位元），π 用 Störmer 公式獨立計算（與 detMath 用的 Machin 不同），並與公開的 π 十六進位前 65 位比對（M7）。

| 函式 | 檢查筆數 | det 最大 | det 平均 | Node 原生最大 | Chrome 原生最大 |
|---|---|---|---|---|---|
| sin | 359,689 | 0.759 | 0.252 | 0.831 | 0.5 |
| cos | 360,023 | 0.764 | 0.252 | 0.831 | 0.5 |
| atan2 | 184,989 | 1.393 | 0.314 | 1.393 | 0.5 |
| acos | 125,895 | 0.875 | 0.257 | 0.875 | 0.5 |
| asin | 125,635 | 0.833 | 0.254 | 0.833 | 0.5 |

（單位：ulp）

- **Chrome 157 的原生三角函數最大誤差 0.5 ulp**，看起來是「正確捨入」的新實作；Node 24 的是 fdlibm 一類（0.83～1.39 ulp）。這就是兩邊分歧的根本原因。
- det 的精度與 Node 原生相同或更好。**所有正式統計一直都是用 Node 原生的精度量的**，所以 det 沒有讓模擬「變得不準」。det 比 Chrome 原生最多差約 0.9 ulp（atan2），約等於 2×10⁻¹⁶ 的相對誤差。
- det 與 Node 原生：sin 99.3%、cos 99.3%、atan2 99.98%、acos／asin 100% 的輸入結果完全相同，其餘差 1 ulp（M3）。
- **判準變更的揭露**：第一版 Gate 要求所有函式 < 1 ulp。atan2 量到 1.39 ulp，與 Node 原生在同一個輸入上完全相同（fdlibm 先算 y/x 再取 atan 的固有誤差）。判準因此改成「sin／cos／acos／asin < 1 ulp、atan2 < 2 ulp，且不比 Node 原生差」，並寫在 Gate 註解裡。這是看過結果才改的，照實記錄。

### 2.3 特殊值契約（M1，57 個案例）

NaN → NaN；sin／cos(±∞) → NaN；sin(±0) → ±0；cos(±0) → 1；atan2 的 ±0、±∞ 各象限依 ECMAScript；acos／asin 定義域外 → NaN；acos(1) → +0、acos(−1) → π；整數次方遇到非整數指數會丟錯。NaN 依「類別」比較，不比 payload。
