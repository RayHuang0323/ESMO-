## 2. 為什麼要修訂

- **B3 的容許值做不到**：容許值是「藍方效果的 5 %」。大部分「計畫 × 路線」格子的藍方效果接近 0，容許值也跟著接近 0；但 D 的標準差和指標的場間波動同一量級。所以在 n = 100 下，就算真實差距是 0 也過不了。這是設計本身的性質，跟觀測到的差異無關。
- **點估計落在容許值內，不等於等價檢定**：這種判法忽略抽樣誤差，小樣本、雜訊大的反而容易過，大樣本、精確的反而容易失敗。

## 5. B1：功能正確性（單獨驗收）

- **每場指標**：該側帶線 tick 裡，由「計畫帶線路對應職業」完成的比例。
- **N/A**：該側整場沒有帶線 tick，就標 N/A 並計數。N/A 不算通過，也不會被默默丟掉。
- **違規**：任何非 N/A 的場次比例 < 0.99，**不論批次是否完整**都是 **B1 STOP**（決定性的功能錯誤）。每輪之間和最後都會檢查；這不是統計上的偷看。
- **PASS**：沒有違規，**而且**每側非 N/A 場次 ≥ 200（原登記每臂的樣本量：100 個 seed × 2 配置），**而且**沒有發生率不對稱。
- **發生率不對稱**：每個 seed 取 o(s) = 兩配置平均的［紅臂紅方有帶線 − 藍臂藍方有帶線］，做配對 z。|z| ≥ zStop 就判不對稱。
- **INCONCLUSIVE**：沒有違規，但 PASS 條件沒有全部滿足。
- **負對照**：legacyMirror 紅臂的 pooled 己方比例必須 < 0.5（判準與原登記相同）。如果沒有失敗，代表儀器抓不到 bug，判 **B1 STOP**。

## 6. B2／B3：等價容許範圍（Δ）

**規則（B2、B3 共用）**：Δ = 0.5 ×「既有 fixture 中，統計上確立（|z| ≥ 3）的最小路線姿態效果」。

- 既有 fixture：`tactic_truth_3a.json`（`21ab068` 版）、`tactic_followup_3a_quickmode.json`、`tactic_followup_3a_replication.json`。三者都在 2026-10-14 以前 commit，早於 laneFrame 修正，也早於原研究。
- 如果在任何行為資料之前已經登記過容許值，就取兩者中較嚴的那個。
- 意義：落在範圍內的不對稱，小於專案在該指標上確立過的最小姿態效果的一半，所以不可能在單側把那個效果藏起來。

| 指標 | Δ | 錨點（全部早於原研究） | 遊戲意義 |
|---|---|---|---|
| gankShare.top／mid／bot | **0.05**（比例的絕對值） | 最小的確立效果是 **0.104620**（quickmode，下路 aggressive，藍方，z 5.54；其餘 0.118–0.129），0.5 倍 = 0.052310。<br>原登記的 B2 容許值是 0.05（2026-10-15，任何行為資料之前；依據 TD-3A-23 §1.4-3 的對照組基準差 0.000／0.009）。<br>取較嚴的 **0.05** | 小於最小 gank 姿態效果的一半 |
| laneForward.top／mid／bot | **1.483147**（三路共用） | 最小的確立效果是 **2.966293**（replication，下路 aggressive，藍方，laneForward.bot，z 4.18）。<br>其他確立的 laneForward 姿態效果是 4.58–6.32（真實性表 std：上路 defensive 藍 +4.58、中路 aggressive 藍 −5.28、紅 −6.32）。<br>0.5 × 2.966293 = 1.483147 | 修正前在同一格的紅藍差距（藍 +2.966 對紅 +0.341，差 2.625）大於 Δ，所以**這麼大的差距不可能 PASS**。<br>Δ 1.48 也遠小於最短的英雄攻擊距離 4（`LogicEngine.js` towerRange 註解：4–8.4） |

## 7. B2／B3 的判定（每列；4 個計畫 × 6 個指標 = 24 列）

- **D 的定義不變**：D(s) = 兩配置平均的［effect_red − effect_blue］；effect = 計畫在該側 − 同側、同 seed、同配置的對照組。
- **N/A**：
  - B2：該側整場 0 次 gank 就沒有 gankShare。
  - B3：該職業對線樣本 < 20，就沒有 laneForward。
  - 某個 seed 的 8 個值有任一個 N/A，該 seed 在這一列就算 N/A（規則和 2026-10-20 定的相同）。
  - n_eff = 非 N/A 的 seed 數。
- **發生率**：每一列都報告 n_eff、n_NA，以及 4 個來源場次側（計畫藍、計畫紅、對照藍、對照紅）的發生率。
  - 發生率的差中差做配對 z。|z| ≥ zStop 就是 **OCCURRENCE_ASYMMETRY**，該列不得 PASS（排除本身可能帶有資訊）。
- **SE** = sd(D)／√n_eff，用常態分位數（n_eff 在數百以上）。

| 判定 | 條件 |
|---|---|
| **PASS** | 90 % 信賴區間 mean(D) ± 1.645·SE **嚴格落在** (−Δ, +Δ) 內（TOST，每列 α = 0.05），**而且** n_eff ≥ 200（常態分位數只用在數百以上的樣本），**而且** sameSign 成立，**而且**沒有發生率不對稱 |
| **STOP** | 99.9 % 信賴區間 mean(D) ± 3.29·SE **整段落在** [−Δ, +Δ] **之外**（證明存在有意義的不對稱）；**或者**證明方向相反：藍效果 |z| ≥ 3.29、紅效果反號且 |z| ≥ 3.29 |
| **INCONCLUSIVE** | 其餘情況 |

- **sameSign**：在藍效果 |z| ≥ 3.29 時才適用，要求紅效果同號。
  - 原規則（|z| ≥ 2 就適用）照樣計算並報告（`sameSignOriginalRule`），但不當 PASS 條件。
  - 原因：24 列、n = 1600 時，即使完全沒有效果，每列也約有 2.3 % 的機率被它擋下，整體很可能光靠運氣就判不過。違反它只會變成 INCONCLUSIVE，不會造成假 PASS。
- **一律報告**：藍／紅效果和它們的 z、mean(D)、sd(D)、SE、z_diff、90 % 與 99.9 % CI、Δ、兩種 sameSign。**z_diff 永遠不是 PASS 條件。**
- **gate 判定**（B2、B3 各自）：任一列 STOP 就是 STOP；每一列都 PASS 才是 PASS；其餘 INCONCLUSIVE。

### 多重比較

- **PASS（宣稱等價）**：採用交集–聯集原則。整個 gate 必須每一列都通過 α = 0.05 的 TOST，才宣稱等價，所以「錯誤宣稱整個 gate 等價」的機率 ≤ 0.05，不需要再校正。發生率與 sameSign 這些附加條件只會讓 PASS 更難。
- **STOP**：每項檢定用雙尾 0.001（zStop = 3.29）。最多約 50 項 STOP 檢定（24 項範圍檢定 ＋ 24 項方向檢定 ＋ B1 發生率），用 Bonferroni 校正後，整體誤判 STOP 的機率 ≤ 0.05。
