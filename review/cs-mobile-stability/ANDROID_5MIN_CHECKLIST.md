# CS Android 真機 5 分鐘檢查清單

**對象**：CS Loading v2（返回同一場沿用模擬結果，約多佔 26–27 MB）上線後的第一次真機確認。
自動化已在桌機模擬 390px／Android UA／記憶體壓力下通過；這份只檢查**自動化做不到的真機行為**。

## 準備（30 秒）

- Android 手機用 **Chrome** 開 `https://rayhuang0323.github.io/ESMO-/`
- 先關掉其他分頁；如果首頁有「返回對戰」，先把那場打完再開始
- 準備碼錶（手機計時器即可）

## 1. 首次進場（約 1 分鐘）

CS → 賽前 → 選地圖 → 選戰術 → 出現 Loading 畫面時**開始計時**，
看到地圖上 10 名角色都出現時**停止**。

- ✅ 正常：60 秒內進入對戰
- ⚠ 記下來：60–120 秒（低階手機可能落在這裡；桌機模擬 CPU 4× 降速＋4G 量到約 91 秒，
  那段時間畫面會停住，是整場比賽在手機上模擬，不是當機）
- ❌ 紅燈：超過 120 秒、分頁自己重新整理、閃退、出現「糟糕」錯誤頁

## 2. 對戰 1 分鐘

切到 **4×**，看角色會走動、開槍、倒地；單指拖曳、雙指縮放鏡頭。

- ❌ 紅燈：角色變成方塊或消失、整個 3D 畫面變黑、明顯卡頓到無法觀看

## 3. 離開 → 返回 ×3（約 1 分鐘）

按左上「← 暫停並離開」→ 首頁按「返回對戰」，重複 3 次，每次都計時。

- ✅ 正常：每次 **3 秒內**回到**同一場**（比分、回合接著原本的，不是從頭開始）
- ❌ 紅燈：每次都重新等很久、比分或回合跳回開頭、返回後黑畫面

## 4. 背景壓力（約 1 分鐘）

對戰中切到別的 App（相機、LINE 都可以）**停 30 秒**再切回來。

- ❌ 紅燈：整頁重新載入、出現「糟糕／網頁無法顯示」、3D 畫面變黑不會恢復

## 5. 收尾（約 1 分鐘）

按「快速完成」→「查看賽後戰報」→「返回 Dashboard」，再開**新的一場** CS，確認能正常進場。

- ❌ 紅燈：賽後戰報打不開、新的一場進不去或 Loading 比第 1 步明顯更久

## 回報格式（複製貼上即可）

```
手機型號／Android 版本／RAM：
1. 首次進場秒數：
3. 三次返回秒數：   /   /
紅燈（沒有就寫「無」，有請附截圖與發生在第幾步）：
```

**只要出現任一 ❌，先不要做任何調整，直接回報**——第一個嫌疑是返回沿用的快取（CS-LOAD-1），
但也可能是既有的 WebGL／記憶體問題，需要用數字確認。

## 真機結果（2026-09-14，Owner）

| 項目 | 結果 |
|---|---|
| 機型 | vivo X80（台灣版，12GB RAM／Dimensity 9000） |
| 1. 首次進場 | 約 10–15 秒；Loading 期間**沒有**「網頁沒有回應」 |
| 2. 對戰 | 無黑畫面、無角色消失 |
| 3. 返回 ×3 | 約 2–3 秒／2–3 秒／2–3 秒 |
| 4. 背景 30 秒回來 | 約 2–3 秒，正常 |
| 5. 結果後開新的一場 | 約 2–3 秒，正常 |
| reload／crash／WebGL context lost | 未發現瀏覽器自動 reload、未發現 crash、無可觀察的 context lost |
| 手動整頁 reload 後重新進場 | 約 10 秒 |

**Owner Final**：`CS_MOBILE_STABILITY_FINAL = PASS`、`CACHE_DESIGN = KEEP`、`DIAGNOSTIC_HOOK = DEV_ONLY`、
`WEB_WORKER_PRIORITY = NOT_NEEDED（現階段）`。

**真機另外發現**：首次進 CS 時短暫看到舊的 primitive（「旗子」）角色，之後才切換成正式 rigged 角色——
列為 closure audit 修正（見 05 Sprint 紀錄）。

注意：這是高階機（Dimensity 9000）。桌機以 CPU 4× 模擬低階手機時首次進場約 91 秒，低階 Android 尚未實測。
