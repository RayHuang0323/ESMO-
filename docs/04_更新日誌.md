### J-close Hotfix 2（2026-07-31）— Ban/Pick 手機捲動與資訊整理

**修正**：手機 Ban/Pick 英雄格只看得到約五列，第六列以後選不到人。
根因不是「捲不順」，是**整頁沒有任何捲動軸**——BanPick 根元素只寫了
`minHeight:100%`、沒寫 `height:100%`，在 AppShell 的
`height:min(88vh,760px); overflow:hidden` 固定盒裡長成 2015px 後被直接裁掉
（390×844 可見 429px ≈ 5.3 列，三種捲動方式都動不了一格）。
這是 Hotfix 1 移除巢狀捲動時留下的回歸——它假設「整頁單一捲動軸」，
但當時是 **0** 個捲動軸。

修法：根元素 `height:100%` ＋ flex column 固定框，英雄格
`flex:1 + minHeight:0 + overflow-y:auto` 成為全頁唯一捲動區
（另加 `overscroll-behavior:contain`、`touch-action:pan-y`、safe-area 底距）。
沒有加高整頁、沒有移除上方配置面板、沒有恢復舊的巢狀捲動結構。

**新增**：英雄搜尋框（比對中文名／英文名／id／稱號／預設路線）、
換篩選或關鍵字自動回到第一列、低干擾捲動提示（細捲軸＋底部漸層）、
「手勢有位移就吃掉這次 click」⇒ 上下滑動不會誤選英雄。

**移除**：Ban/Pick 的兩處「誰克制誰」呈現（摘要的「⚠被 XXX」欄、
選角動態的「（克制你的 XXX）」）。`archCounterScore` 與 AI 選角行為一行未改，
適性／位置衝突／陣容需求全部保留。未來建議另開 Hero Codex「對位」頁籤。

驗證：新增 `tools/shot_banpick_hotfix2.mjs` **252/252**

### Milestone K（2026-07-31）— Hero Codex 對位頁籤與 Matchup Data Contract v1

**新增**：`src/data/heroMatchups.js`——英雄多對多關係的**唯一來源**（Matchup Contract v1）。

```
HERO_MATCHUPS[heroId] = { strongAgainst: Entry[], weakAgainst: Entry[], synergies: Entry[] }
Entry = { heroId, reason, source, confidence }
source     ∈ design（設計資料）| inferred（系統推測）| verified（實戰驗證）
confidence ∈ low | medium | high
```

原始表不 export，UI 只能走純函式（`getHeroMatchups` / `getStrongAgainst` /
`getWeakAgainst` / `getSynergies`）；查無資料回**穩定空結構**不 throw；資料深凍結。

**新增**：Hero Codex 第五頁「對位」，頁籤成為 `概覽｜數據｜技能｜戰術｜對位`。
三區＝較有優勢／較難應付／適合搭配。每張卡有頭像、中英名／定位、原因摘要、
來源標籤與信心程度；有 `inferred` 條目即顯示
「此內容依英雄定位與技能特性推測，不代表真實玩家勝率。」；
無資料顯示「目前尚無已整理的對位資料。」

**資料誠實性**：本輪 10 隻英雄、42 筆——**design 36 筆、inferred 6 筆、verified 0 筆**。

對局樣本，頁面底部主動聲明這件事。未來啟用 `verified` 的三條可行來源與各自前提
