# 戰隊發展系統 v1.5

## 目的

R59.1 將 R59 的 8 個平面節點整理成四條各 5 項的俱樂部長期發展路線。戰隊發展只屬於俱樂部，不寫入單一選手能力，也不取代選手訓練、個人天賦或比賽公式。

## 路線

每類採 2 個基礎、2 個進階、1 個專精節點，節點顯示 Lv.0 / 3、三格進度與下一級效果：

- 通用：訓練流程優化 → 恢復中心；數據分析室、成長支援；球探支援。
- MOBA：英雄研究室 → Ban/Pick 情報；對手研究、戰術準備；賽前分析。
- CS：地圖研究室 → 團隊磨合；Demo／對手分析、戰術準備；賽前情報。
- 經營：球探網絡、青訓資料庫；合約管理、贊助拓展；財務規劃。

路線前置條件只限制節點順序，不限制選手角色或 roster 組成。既有的一次性解鎖節點保留三格路線，但只有第一級有實際讀取點；後續等級會清楚標示「尚未開放」。

## 真實效果與規劃中內容

目前正式生效的 consumer：

- 訓練流程優化：每級縮短訓練排程 1 天，沿用 `profileStore.assignTraining`。
- 恢復中心：每級每日恢復 +4，沿用 `profileStore.advanceDay`。
- 球探網絡：每級縮短球探報告 1 天，沿用 `RecruitScreen`。
- 英雄研究室、Ban/Pick 情報、地圖研究室、團隊磨合、青訓資料庫：沿用既有賽前／招募支援提示。

數據分析、成長支援、對手研究、Demo 分析、戰術準備、賽前分析、合約、贊助與財務等節點目前沒有乾淨的正式讀取點，因此只作為未來路線展示，不可投入、不會產生假 bonus。

## 相容與驗證

狀態仍使用 `TeamDevelopmentState.v1`，舊存檔的 `availablePoints`、`spentPoints`、`ranks`、`updatedAt` 讀取方式不變；未知節點會被忽略，既有節點等級會依新上限清理。`teamDevelopmentEffects` 只處理有 `effect` 且非規劃中的節點。

`tools/check_team_development_v1.mjs` 已升級為 R59.1 focused verifier，覆蓋四分類、20 節點、Lv.0→3、前置條件、重複投入、真實效果、規劃中節點不生效、Store runtime hook、GSAP / reduced-motion UI 靜態檢查。

## UI 與動態回饋

戰隊發展頁增加俱樂部長期方向、四類投入程度、目前分類的發展路線與節點卡片。節點卡片顯示名稱、玩家語言效果、等級、三格進度、下一級效果、影響範圍、前置條件與投入按鈕。

GSAP 只用於分類切換、節點 stagger 進場、發展點變更提示與升級 pulse / progress fill。`useGSAP` 以 scoped context 清理，並以 `prefers-reduced-motion` 跳過動態；沒有加入 ScrollTrigger 或大型動畫架構。
