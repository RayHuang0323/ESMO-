# MOBA 裝備設計守門（Item Design Guardrail）v1

> 狀態：2026-09-16 由 Owner 於 M4c Closure 訂為**長期守則**，不限於單一 milestone。
> 適用範圍：`src/battle/moba/items/itemCatalog.js` 的所有 T1／T2／T3 與其 `effects`／`unique`。

## 0. 守則原文（Owner）

> ESMO 裝備需維持成熟 MOBA / LoL 類型的裝備框架，但**不得為了數值達標而把所有裝備同質化**。
> 每個 T3 Item Family 必須保留：明確角色定位／核心屬性方向／Power Fantasy／與其他同類裝的選擇差異／situational / counter 價值。
> Balance 時**優先調效率與幅度**，不要直接移除一件裝備的核心特色。
> 若「數值 Gate」與「裝備 Identity」衝突，**先回報**，不要為了過 Gate 把特色砍掉。

## 1. 每件 T3 必須同時滿足的五項

| # | 條件 | 判定方式 |
|---|---|---|
| 1 | **明確角色定位** | 能用一句話講出「誰買、為什麼買」，且對得上 `BUILD_PATHS` 中的位置 |
| 2 | **核心屬性方向** | 主屬性不可與同族其他件重疊到難以區分（例：同族三件不可都是純 AD＋HP） |
| 3 | **Power Fantasy** | 該屬性的實際幅度要讓玩家感覺得到；屬性存在但幅度趨近於零 ⇒ 視為已失去 |
| 4 | **同族選擇差異** | 同 family 三件之間要有真實取捨，不能是「同一件的強弱版」 |
| 5 | **situational / counter 價值** | 至少有一種敵方陣容或局勢會讓它從「不買」變成「必買」 |

第 3 項是本守則最容易被平衡工作侵蝕的一項：**把數值一路往下調到剩殘值，形式上保留了屬性，實質上等於移除特色**。這種情況一律視為違反守則。

## 2. Balance 時的調整優先序

1. **效率**（同樣效果、價格／組件變貴或變便宜）
2. **幅度**（同樣屬性、數值增減）
3. **觸發條件**（效果的門檻、冷卻、射程）
4. ~~移除或歸零核心屬性／效果~~ ← **需 Owner 明確授權才可執行**

## 3. 衝突處理流程（Gate vs Identity）

當「數值 Gate 未達標」而唯一剩下的手段會踩到第 1 節的五項之一時：

1. **停手**，不要自行把特色砍掉換取過 Gate。
2. 回報三件事：Gate 差多少、還剩哪些可調參數、若硬過 Gate 會犧牲哪一項 identity。
3. 等 Owner 裁決要「接受偏差」還是「授權動 identity」。

### 已發生的案例（2026-09-16，M4c.1）

射手實戰輸出倍率 2.18 高於 1.8–2.1 上緣 0.08。剩餘可調空間只有暴擊鏈，而暴擊鏈**再往下調就會讓 family A 失去「暴擊」這個核心屬性方向**（滿裝暴擊率已降到 0.15）。依本守則回報後，Owner 裁決：

- 射手 **停止調整**，2.18 記為 **ACCEPTED WITH KNOWN DEVIATION**。
- 不得再降低目前的 `critChance` / `critDamageAmp`。

此案例即為本守則第 3 節流程的第一個實例。

## 4. 新增裝備時的檢查點

新增任何 T3 前，先確認：屬於哪個 family、要取代或補足哪個定位、與同族既有三件的取捨是什麼、哪種敵方陣容會讓它變成必買。四項答不出來就不要新增。

同時確認它在 `BUILD_PATHS` 中**實際可達**（見 `MOBA_裝備平衡收斂_M4c_v1.md` §4 的可達性問題）：只掛在 `fallback` 第 3 順位之後的裝備，在目前的經濟節奏下等同不存在。
