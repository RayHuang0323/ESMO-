# R63 進行中比賽恢復與速度控制

## 決策

R63 沿用既有 `MatchSession.v1`、`profileStore`、MOBA `LogicEngine`、CS `simulateFps` 與既有 result / progress transaction。`ActiveMatch.v1` 是掛在同一份 matchmaking session 內的可恢復執行狀態，不是第二套 Match、Router 或結算來源。

正式啟動後，session 會保存 `matchId`、mode、對手、出賽名單快照、gateway seed、startedAt、phase、simulation time 與最近 snapshot。Battle view 卸載、返回或 refresh 時以 paused snapshot 保存；目前 v1 不做背景模擬。

## Resume

- 首頁與既有賽前入口讀取 `activeMatchView()`，顯示對手、模式、模擬進度與「返回進行中的比賽」。
- restore 只呼叫既有 `resumeMatchSession()`，再依保存的 phase 回到 MOBA／CS 原流程。
- MOBA 以同一 seed 與同一 battle config 建立正式 `LogicEngine`，以固定 simulation tick replay 到保存時間後繼續。
- CS 以同一 seed 建立正式 `simulateFps` frame stream，從保存的 frame cursor 繼續呈現。
- launched 且具 ActiveMatch snapshot 的場次不受舊 TTL 誤判；legacy launched 無 snapshot 只顯示無法恢復，不冒險重建。

## Speed / fast finish

MOBA 與 CS 共用 `MatchSpeedControls` presentation，使用安全的 `1x / 2x / 4x` 選項與相同的「快速完成」確認流程。底層仍可依 simulator 實作不同：MOBA 改變 tick interval，CS 改變 frame playback interval，均不改正式模擬輸入。

快速完成會從目前正式狀態跑到終局：MOBA 使用目前的 `LogicEngine` 分塊 tick；CS 使用目前 frame 到正式 simulation 最後 frame。結果仍進入既有 BattleResult／CsMatchResult、progress、reward 與 idempotent settlement，不能重新抽 seed 或另算勝負。

## 終局與放棄

完成後 ActiveMatch 進入 `finished`，卸載 cleanup 不會覆寫 terminal 狀態。確認放棄後進入 `abandoned`，清除可恢復資格；它是次要危險操作，不是返回比賽的必要步驟。

## 驗證限制

`tools/check_r63_active_match.mjs` 覆蓋 ActiveMatch 建立、snapshot、TTL、resume、abandon、MOBA／CS deterministic fast finish、共用 speed controls 與單次結算來源。Node 可證明資料與 deterministic contract，但無法證明真機觸控、safe-area、瀏覽器 refresh 體感或 FPS；這些仍需人工驗收。
