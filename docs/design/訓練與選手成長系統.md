# 訓練與選手成長系統

## 時間邊界

### 開發版

- `meta.days` 是 ESMO 的遊戲世界日曆。
- 玩家按「推進訓練日」即可立即推進一天，作為開發／測試工具與經營世界時間的操作入口。
- Training 不使用 `setTimeout`、`Date.now()` 等待、離線掛機 timer 或前端模擬 Server Timer。

### 正式線上版方向

未來由 server-authoritative training schedule 管理短／中／長訓練，前端只顯示伺服器提供的排程與結果。
正式版不把一個遊戲日直接定義為現實 24 小時；真實分鐘／小時的時間制度與後端 timer 屬於第二階段。

## Training v1.1 成長公式

每門課完成一次的實際成長為：

`課程基礎成長 × 潛力空間係數 × 年齡係數 × 學習能力係數 × 狀態係數`

- 潛力空間越小，成長越慢；能力不超過 `potential`。
- 年齡只影響 Training efficiency：年輕略高、成熟期為基準、高齡平滑下降。
- `learning` 以溫和係數影響同一門課的成長，不造成 2～3 倍極端差距。
- condition／energy 影響效率；疲勞會降低成長，但不會讓成長無故歸零。

純規則集中在 `src/data/trainingCalculator.js`。UI 預估與 `applyCourse` 共用同一個
`TrainingResult`；Store 負責推進 `meta.days`、寫入選手與 `growthLog`，不建立第二套資料來源。

## 本輪不包含

本輪不加入教練等級、訓練設施、天氣、複雜士氣乘數、傷病、critical growth、付費加速、
新課程或真正的 backend timer。

## 選手健康規則（2026-08-25 產品裁決）

### ESMO 不採用選手隨機受傷／傷停機制

選手不再有「受傷」這個 gameplay 狀態。任何來源都不得產生
`injured` / `injuryDays` / 傷停 / 療傷：

- 比賽結算
- 體力過低
- 連續出賽
- 隨機 / 決定性抽籤
- 訓練

受傷也**不得**成為出賽資格條件。玩家看得到的狀態只有：
**正常 / 疲勞（體力不足）/ 其他既有的名單狀態（未登錄、重複、席位）**。

歷史：Milestone O2 曾實作完整的受傷系統，2026-08-25 依產品裁決整套移除
（branch `feature/remove-player-injury`）。舊存檔仍可能帶著欄位，
runtime 讀得到但完全不用，見 `docs/09_技術債務清單.md` TD-29。
守門：`tools/check_no_player_injury.mjs`。

### 仍然成立的「休息」壓力來源

移除受傷**不代表**選手可以無限出賽。壓力改由單一來源構成：

```
連續出賽（matchStreak）
   → 單場體力損耗加重（12 + streak × 3）
   → 體力下降
   → 體力 < CONDITION.unfitBelow ⇒ exhausted ⇒ 不可出賽
   → 需要休息日 / 訓練日 / 輪換替補
```

同時體力也直接進入本文件的訓練公式（`conditionEfficiency(energy)`）⇒
硬撐出賽的選手**練起來也比較慢**。這是輪換的第二層代價。

### 年齡不在移除範圍內

本節只取消受傷。**年齡（`age`）完整保留**，且仍然是訓練公式的因子之一
（`ageEfficiency`，見上文 §年齡係數）。本輪沒有改動任何成長公式，
`TRAINING_FORMULA_VERSION` 仍是 `training-growth.v1.1`。

年齡推進、成長期／巔峰期／衰退期、退休、新人生成、AI 換血、off-season
全部屬於 **Season vNext**，另案設計，本輪一律不實作。
