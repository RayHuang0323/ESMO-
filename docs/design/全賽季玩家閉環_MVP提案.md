# 全賽季玩家閉環 MVP 提案

- 日期：2026-11-04。依 Owner Review（3a-B 整合最後一輪）第 E 項與決策 4。
- **狀態：提案，等 Owner 核准範圍。** 沒有開工，沒有改產品程式。
- **基準：** 從 Owner 放行整合之後的 main 開始；MOBA 維持 v20，兩個 v21 旗標維持關閉。方案 B 的 MOBA 平衡重設暫緩。

## 1. 一句話目標

同一份存檔，玩家能從開新局一路玩到第二季第一場，中途關掉重開也能接著玩，桌機和手機寬度都走得完。

**這一輪優先證明「連得起來」，不是加新東西。** 每個環節今天幾乎都有自己的 Gate，但沒有任何一支 Gate 把它們接成一次遊玩（`check_*` 多半從佈置好的存檔開始）。

### 還沒查證、要先回答的問題

這些是從文件讀到的疑點，**還不能當成缺陷**：

1. **雙賽制日曆。** `04_Roadmap.md` 寫「CS／MOBA 雙賽制的賽季曆整合」尚未開始；`CS_賽事系統架構規格.md` D5 的設計是共用日曆、各自結算、賽季編號可以不同步。現況做到哪裡要實測。
2. **賽季和生涯年度的邊界。** 一季 84 天（12 週），休賽期綁生涯年度。兩者對不對得上、MOBA 和 CS 只觸發一次休賽期，要實際走一次。
3. **一季到底幾場。** 量過 MOBA 一季 35 場（聯賽 14 ＋ 巡迴 3 站 × 7）。CS 聯賽＋Major 加上去的實際負擔還沒量，這決定每週會不會太擠。
4. **日曆卡死。** 有未收尾賽程時 `advanceDay` 推不動，休賽期也會擋世界時間。雙賽制下有沒有互相卡住的組合，要在連續遊玩裡驗。

**建議順序就是上表。** W1 比 W2 先做，因為它快又穩定，W2 的失敗才分得清是流程問題還是環境問題。

### 瀏覽器 Gate 怎麼控制長度

逐場走完整季不實際：單場 CS 正式流程就要將近 1 分鐘，一季 35 場 MOBA 再加 CS，單支 Gate 會超過一小時，也更容易被記憶體保護停掉。

- **Node（W1）：** 每一場都是真模擬，一場不省。
- **瀏覽器（W2）：** 真 UI 只走**第一週、最後一週、休賽期、第二季第一場**。中間週由同一批 store action 推進，並在報告明確標示「這段不是 UI 操作」，**不寫成瀏覽器驗過**。
- 全程 UI 打完一整季，留給 W4 的 Owner 試玩。

## 5. 驗收不變量（提案，要 Owner 核准才算數）

W1、W2 共用：

1. **帳對得上：** 期末資金＝期初＋所有帳本交易總和，沒有帳外增減。
2. **一場一次：** 每個 `matchId` 只入帳一次；重整、返回、重開都不會多。
3. **排名同源：** 積分榜可由已寫入的賽果重新算出，逐隊相等。
4. **賽季單次結算：** 獎金、榮譽、粉絲獎勵各發一次；重跑結算不變。
5. **存讀恆等：** 每個節點存檔再讀回，核心狀態相等（在 `saveBundle` 定義的範圍內）。
6. **永遠走得出去：** 沒錢、缺人、合約到期都能走到下一季，不會卡死。
7. **推導不落盤：** 生涯階段、市場價值、AI 名單不得寫進 `players[]`。
8. **v20 不變：** 全程實際對局記 `moba-sim.v20`，存檔沒有 v21 標記，戰術書不出現。
9. **零錯誤：** 全程 console／page error 為 0，桌機與 390 都沒有水平溢出。

**不設平衡門檻。** 勝率、經濟數值高低這一輪只記錄，不當紅燈，避免又變成新一輪平衡研究。

## 6. 明確不做

- 大型重構、第二套 Store／賽程／賽事邏輯。
- 新賽事、新賽制、升降級、轉會市場擴充、AI 隊伍新演進。
- MOBA 平衡重設（方案 B 暫緩）、啟用 v21、重開 Phase 3a-B 或第七輪。
- 改 CS 模擬。斷點如果在 CS 線，記錄後交 CS 線處理。
- 重錄 Golden、放寬 Gate。
- 真 Supabase、手機真機：維持已知缺口，**但不宣稱驗過**；真機排進 W4 或之後，由 Owner 決定。

## 7. 風險

| 風險 | 處理 |
|---|---|
| W0 發現斷點很多，範圍膨脹 | 只修「阻斷」；其餘進清單，由 Owner 排 |
| 斷點落在 CS 或共用引擎 | 不順手修，停下來回報 |
| 瀏覽器長 Gate 被記憶體保護停掉 | 分段續跑、單線，且不與其他長任務同時跑 |
| Gate 用佈置資料造成假綠 | 開局只走 `startNewGame`，佈置都要在報告標明 |
| verify 的訊號弱（47 段停在來源指紋，TD-3aB-1） | 這個 MVP 不靠那些段當證據；恢復訊號是 CS 線的另一項工作 |

## 8. 要 Owner 決定

1. **這個範圍可以嗎？** W0–W4，只修阻斷。
2. **MVP 是否要求同一年內 MOBA 和 CS 都打完？** 建議要。玩家本來就可以兩邊都玩，雙賽制也是目前最沒有驗過的部分。如果 CS 聯賽負擔太重，W0 量完再討論。
3. **手機真機放在哪個階段？** 建議 W4，因為這裡只能驗 390 寬度。
4. **合併時機：** 這個里程碑建議在 Owner 放行整合、main 更新之後才開始；否則 Gate 會綁在測試分支上。
