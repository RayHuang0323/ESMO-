# CS P0 視覺穩定性與防回歸契約

狀態：`CS_P0_VISUAL_STABILITY = OWNER_ACCEPTED`

本文件是 CS FPS P0 視覺事故的長期 root-cause、production fix 與 regression contract。未來修改 CS renderer、playback、camera、roster identity 或 Battle viewport 前，必須先讀本文件。

## 1. Background

本輪曾同時出現四個表面相近、實際不同的問題：人物消失、Camera Auto Director 反覆 recovery、Canvas compositing jitter，以及週期性 Flash + Ghost Frame。最後一項不是 Canvas geometry 的延伸症狀；兩者必須分開維護與驗證。

Owner 已完成 Android 真機最終驗收，四項全部 PASS。

## 2. Four Production Incidents

### A. Player Identity Visibility

- Symptom：部分或整隊人物消失，但 simulation 仍有玩家資料。
- Root Cause：simulation 使用 authoritative `effectiveRoster`，renderer identity path 曾使用另一份 roster / player identity，造成 ID mismatch；identity miss 又被錯誤當成 death presentation。
- Trigger：map transition、BO3 map、substitute / reopen、roster pool rebuild。
- Fix：simulation 與 renderer 共用 authoritative `effectiveRoster`；renderer pool 隨 roster/map identity 正確重建；identity miss 只保留可恢復的 diagnostic state。
- Contract：不得建立 module-level `ACTIVE_ROSTER` 第二來源；identity lookup failure 不得隱藏玩家；只有 authoritative `player.dead` 可以隱藏人物。
- Gate：Renderer visibility `24/24`、CS-A2 identity `10/10`、C2A `13/13`、C2B `14/14`。

### B. Camera Recovery Loop

- Symptom：Auto Director 反覆跳回 overview，造成鏡頭亂切。
- Root Cause：舊邏輯把「任一 alive player 離開 viewport」當成 recovery 條件。
- Trigger：單一玩家被鏡頭裁切、局部 framing、視角切換。
- Fix：`evaluateFpsCameraRecovery` 只允許整隊 alive players 全部離開 viewport 時 recovery；恢復後仍沿用既有 camera director。
- Contract：單一 player 或部分隊員離屏不得 recovery；只要該隊仍有一人可見就不得 recovery；整隊 alive viewport = 0 才可 recovery；rapid recovery loop 必須為 0。
- Gate：Camera recovery `8/8`；browser long-run 讀取 bounded recovery counters。

### C. Canvas Geometry Jitter

- Symptom：Canvas 整體短暫晃動；曾觀察到 roster height `262 ↔ 263px`，造成 ancestor sub-pixel geometry shift。
- Root Cause：PlayerRow / roster state update 參與了 WebGL Canvas ancestor sizing 與 compositing boundary。
- Trigger：kill、roster status、ScoreBar、feed、round overlay、其他 HUD state update。
- Fix：`BattleViewport` 固定為 `StableCanvasRegion`、`CanvasLayer`、`FrameDecorationLayer`、HUD siblings。Canvas 不再直接承擔 border-radius / clipping / shadow compositing boundary；裝飾保留在 decoration layer。
- Contract：HUD / roster / PlayerRow 更新不得改變 StableCanvasRegion 的 x/y/width/height；只有真正 viewport resize 可以改變 geometry。`contain: layout paint`、`isolation: isolate` 是目前實作細節，不是不可替換的 contract；真正 contract 是 geometry isolation。
- Gate：StableCanvasRegion geometry verifier；browser long-run samples 的 layout shift 必須為 0。

### D. Periodic Flash / Ghost Frame

- Symptom：約每 2–3 秒短暫 flash，緊接著看到前一幀或另一 frame 的殘影；Canvas geometry 已穩定、camera 也不跳。
- Root Cause：playback transition 呼叫 `setFIdx(next)` 後，React asynchronous commit 尚未完成；同一 RAF 仍從舊的 live fIdx 讀取，產生 previous-frame extra render。`fIdx` 是高 correlation trigger，不是 playback simulation 的 bug。
- Trigger：fIdx transition 同時更新 feed、multikill、casts、comms、round overlay 等 presentation state。
- Fix：每次 authoritative playback transition 先執行 `liveRef.current.fIdx = next`，再執行 `setFIdx(next)`；seek / reset 也使用同一 publisher。simulation、RAF、HUD data 都照常更新。
- Contract：RAF 讀取的 live fIdx 不得落後 authoritative transition；不得改回只讀 asynchronous React state；不得在同步 ref 前呼叫 `setFIdx`；stale mismatch 必須為 0。
- Gate：`RAF_FIDX_COHERENCE`、browser long-run 180 秒以上，stale mismatch = 0、duplicate RAF/render = 0、browser errors = 0。

## 3. Trigger ≠ Root Cause

`fIdx` 曾與 Ghost 高度 correlation，但 fIdx playback 本身不是 Bug，不得 freeze fIdx、skip simulation 或停掉 HUD。PlayerRow / roster update 是 Canvas jitter 的 trigger，不是應被停用的功能。Flash/Ghost 與 Canvas geometry jitter 是兩個不同 failure mechanism。

## 4. Eliminated Hypotheses

以下方向已做過實際 isolation，沒有消除 Periodic Flash/Ghost，未來發生同一症狀時不得無 evidence 地重跑整套歷史調查：

- transient lights
- transparent FX
- shadows（shadow pass 正常；不是 sole root cause）
- wall fade
- static camera
- fixed DPR / resize
- duplicate RAF
- duplicate render
- camera projection spike
- historical FPS Git bisect
- Canvas clipping removal（對 Canvas Jitter 有幫助，但沒有解掉 Flash/Ghost）
- React separate-root / compositor isolation（未能單獨消除 Ghost）

若新 evidence 明確推翻其中一項，才重新開啟該假說，並在新紀錄中附 correlation evidence。

## 5. Forbidden Regressions

- 不得重新建立第二份 roster identity source。
- 不得把 identity miss 當作 death。
- 不得退回 any-player-offscreen camera recovery。
- 不得讓 HUD / roster 參與 StableCanvasRegion sizing。
- 不得移除 live fIdx sync 或改成只依賴 React state。
- 不得以 React.memo、freeze fIdx、skip HUD、固定假資料、關閉 shadows 作正式修法。
- 不得保留 MANUAL_GHOST_MARK、capture buffer、periodic detector、temporary tunnel / isolation flag 到 production。
