**Sprint 29B6 完成（MOBA Camera Control, Real Replay and Battle UI Fix）。**
依 Ray 29B5 部署後的手機實測修四項，並正式定義 2.5D 視角方向：

- **地圖不能移動根因**：`MobaView3D` 的 `<OrbitControls enablePan={debug}>` —— `debug`
  預設 false 且 `GameView` 從未傳過 ⇒ **平移永遠關閉**，能動的只有「旋轉」，
  而 2.5D 正交戰場根本不該旋轉。修法：**移除 OrbitControls 與 CameraRig**，
  `battle/cameraStore.js` 成為 pan/zoom 的**唯一狀態源**（clamp 於 `WORLD_BOUNDS`），
  `BattleCameraController` 是**唯一**把 pan/zoom 套到相機的地方（固定俯角、零旋轉），
  手勢（單指 pan / 雙指 pinch / 滾輪 / tap 英雄 / 雙擊回導播）在 `MobaView3D`。
- **2.5D 政策**：新增 `docs/design/MOBA_2.5D視角與資產策略.md`（2.5D 正交戰術視角、
  不追求自由旋轉 3D、可 pan/zoom 不旋轉、資產走 glTF/自有低模/可商用，
  **不使用 LoL / 傳說官方素材**）。
- **真實戰場重播**：新增唯讀 adapter `replayPresentationSource`
  （`frame → {prev, snapshot, subTRef}`），`MobaView3D` 加 `source` prop ⇒
  **重播與現場共用同一套 3D 戰場**，SVG 小地圖降為輔助 inset。不重新模擬、
  不掛 `useBattleFeed`、不重複發獎；舊 replay（無 mapMeta / 100×100）退回 2D SVG。
- **Objective 死亡同步根因**：英雄畫在 `lerp(prev→snapshot, subT)`（落後最多一個 tick），
  中立目標卻直接讀 `snapshot` 不插值 ⇒ 相位差；加上血條「追值」殘留 ⇒
  「血條還剩兩三成、模型突然消失」。修法：目標 hp/存活改走**與英雄同一條插值時間軸**
  （死亡撐到 `a=1`）、fade 0.5s → **1.1s**、死後不顯示 HP 條、坑位留 absent 環。
- **戰報 safe area 根因**：沒人定義過 score header 安全區 —— `BattleTimeline` `top:96`、
  `GameView` 控制鈕 `top:92` 都壓在 `BattleHUD`（`top:6`、高約 120px）的藍紅勝率條上。
  修法：新增 `battle/ui/battleLayout.js`（`SAFE_TOP=138` ＋ **z-index 統一表**），
  戰報與控制鈕一律從 `SAFE_TOP` 起；320/360/390/430 不溢出、不撞控制鈕欄。

29B3/29B2/29B1、runtime29 44/44 巢狀、regress/regress2、build）。
